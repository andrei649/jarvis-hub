# H18.31 native selected images

Date: 2026-10-09. This native slice uses the selected Ollama routes already merged on main (`/api/vlm/composer/active-images`, `/selected-prepare`, `/selected-chat`), not the earlier PR1233 `/prepare`/`chat-prepared` routes. It requires the backend owner principal: the selected routes have both `user_guard` and `owner_web_principal`, so the client sends both configured trimmed user/admin headers. A user-only token is refused. No cloud fallback, camera, automatic retry, implicit text-chat image attachment, or automatic first-session creation is added.

The user opens Images in Chat and chooses up to four new images from the system photo library. Selection is explicit and one asset per picker invocation. The picker returns base64; the app validates its length, dimensions and PNG/JPEG/basic WebP signature, infers MIME from the exported bytes rather than the original asset metadata, freezes the exact `data:<mime>;base64,<bytes>` string in mounted memory, and hashes that full string using Expo Crypto. It never re-reads a mutable URI between review and send. Each new image is at most 4 MiB decoded, new bytes total at most 8 MiB, and new plus selected prior active images at most eight. The server remains the final raster/staticness and 20 MB Ollama wire-payload authority. GIF, extended WebP, HEIC-encoded exports, and other unsupported exported formats are refused by this native picker path; an HEIC original exported by the picker as valid JPEG can be accepted. A PNG signature does not establish that the raster is static; the server checks full decode and animation. Its library export may be a JPEG representation of a different original; the exported frozen bytes, not the library original, are what the owner reviews and submits. No picker URI or data URI enters chat storage or logs.

A concrete H18.30 session ID is required on list, prepare, and send. A first image conversation uses an explicit `/new` action; History can explicitly resume an existing session. Process-local active handles are fetched for the exact session and agent, rendered as question/count selectors without invented thumbnails, and never persisted. A valid empty active list does not prove historic image turns lacked images; an unavailable list is shown separately from empty. Prepare sends only exact prompt, ordered full-data-URI digests, and selected handle IDs. The review card displays the returned selected model, sanitized loopback destination, count, “local to Hub host,” and unprobed `reachable:null`. Editing the question/selection, changing agent/session/hub, backgrounding, or a new text turn invalidates review. The one-use review token expires after 60 seconds server-side; native expires the visible review at 55 seconds.

Submit takes the `Conversation` shared turn lock, so text streams and selected image turns cannot interleave locally. Before selected-chat dispatch, the app writes a bounded scope/session/agent outcome marker to AsyncStorage; failure or timeout of that write prevents dispatch. The marker contains only opaque scope, session ID, agent, attempt ID and version—no prompt, image, handle, review token, endpoint, or credential. At most eight unresolved markers are retained; a ninth request is refused rather than evicting a prior unknown result. Only the same attempt may clear its marker after a verified committed response or a definite 401/403/409/422 precommit refusal. A lost/aborted/5xx/malformed/stale response remains unknown. The user must open History and explicitly acknowledge the possible duplicate before another review; absence of a turn in the last-20 History response is not proof that the server did not commit. The existing History resume mutates the Hub's active session, so it is always an explicit owner action. No idempotency key exists.

AppState transitions caused by the still-owned OS picker are exempt from generic background cancellation. After its result, the app waits at most 15 seconds for an active state and rechecks mounted scope, session, agent and conversation revision before accepting it. Other background transitions revoke review/send work, clear image bytes from mounted state, and preserve a dispatched unknown marker. An ignored native fetch/response-body abort is bounded by independent GET 5 s, prepare 10 s and send 180 s deadlines. React Native `response.text()` is buffered before the post-read length check; the Content-Length precheck and 32 KiB active-list/8 KiB prepare/128 KiB send JSON caps are best effort against dishonest oversized replies, not streaming memory bounds. `reachable:null` is not a model readiness probe, and the destination is local to the Hub host, not necessarily the phone.

Only validated user/assistant text is appended after a matching committed response. The user text includes the backend's image-count marker; settled chat persistence projects an allowlist of text fields and drops any extra image structures. Active image handles and temporary image bytes are not persisted. If a response confirms commit after the UI session or scope changed, it is not appended to that topic; the old marker remains unknown until explicit inspection. A server 502 or transport loss can occur after a commit, so no automatic retry is safe. Process-local active bytes may expire or evict, and there is no native or backend thumbnail/download route for these handles.

Source unit: `src/api/selectedImages.ts`, `src/images/snapshot.ts`, `src/storage/selectedOutcome.ts`, `src/components/SelectedImages.tsx`, minimal `ChatScreen`/`Conversation`/chat-storage integration, their Jest and mounted native tests, and SDK58 image picker/Crypto manifest additions owned by the root agent. The root agent owns ledger/status changes and global mobile/native/export validation. Rollback this native unit and its direct dependency additions without touching the merged selected-route backend or H18.30 conversation endpoints. No live Ollama call is made by tests; on-device owner-token/model acceptance remains a separate operational check.
