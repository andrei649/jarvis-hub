## Implementation and verification

Connected entity buttons are deduplicated and exclude self-links; they can load entities outside the initial 50-row list. Detail responses must match the requested name, and history must match its requested subject. The graph reuses the connection's opaque `chatScope` identity to hide prior-hub data while a new request starts. Search, selection, mode changes, reconfiguration and unmount cancel outstanding reads and invalidate callbacks. Independent list, current-facts, relation and history errors remain visible without fabricated empty results.

Each read has a ten-second deadline. Content-Length is checked before reading when available, and actual UTF-8 text is checked against one MiB after `Response.text()`. This is a native-compatible buffered response check, not proof of a streaming allocation cap. The UI shows at most 50 entities and 100 relation/fact/history rows, with truncation labels. It reuses the existing user-guarded routes and accepts an admin-only connection.
