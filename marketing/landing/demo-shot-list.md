# Jarvis Hub demo shot list

This is the owner-facing capture checklist for the 60-second teaser. It is distilled from
`docs/marketing/TEASER_PACK.md` section 6 and deliberately stays in the marketing tree next to the
static landing page.

Owner records the actual footage in M4. Demo mode must be clearly badged whenever the shot is not
captured from real product data.

| Shot | Capture | Notes |
|------|---------|-------|
| Hero cockpit at rest | HUD at rest, agent network brain alive, void/cyan palette visible | Use for the first landing/social hero image. |
| Trust Center | Audit chain reads verified, with the locality meter visible | This is the governance proof point. |
| Governed-autonomy moment | Approval queue or phone decision card beside the task it gates | The action must visibly wait for approval. |
| Morning brief | Prioritized digest, follow-ups, and one concrete next action | Sells proactivity without pretending the system did invisible magic. |
| Frigga strict-local badge | Frigga/family surface with strict-local status visible | Privacy proof point; do not show personal family data unless owner-approved. |
| WorldView globe | Optional WorldView 4D OSINT companion shot | Mark as companion surface, not core Jarvis Hub UI. |

## Capture rules

- Use real HUD data whenever possible.
- If demo mode is used, keep the demo badge visible for the entire shot.
- Do not stage fake private data.
- Do not crop away the approval, audit, locality, or strict-local proof points.
- Keep captions calm and specific: no hype words, no claims that are not present in the repo.
