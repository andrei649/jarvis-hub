## Behavior

The fixed `JARVIS_ROLE_VIDEO_TRANSIENT_RETRIES` setting defaults to zero and accepts
only zero or one. One allows a single extra primary request after an owned typed
connection/remote-protocol error or bounded HTTP 408/5xx response. Ordinary
timeouts go directly to the already approved fallback path; fallback candidates
still receive only one attempt. HTTP 408/5xx exhaustion does not authorize a
different provider. Auth/payment/rate/model failures retain their separate fallback.

Enabled retry policy is an internal part of the signed task class, never a new
caller-supplied argument. Policy changes stale execution; default-zero approval,
consent, notice and result formats remain compatible. The notice identifies the
primary retry budget and candidates within 200 characters. Enabled results include
fixed failed-attempt categories and one-based route attempt provenance.

Every retry reconstructs its body and owned client after cleanup and renewed task,
kernel, chain, consent and policy checks. Prepared video is reused without another
source URL fetch. Per-attempt single-send markers, actual-use checks and existing
180/65/60/35-second total/attempt/client/source limits remain authoritative.
No retry follows a source/factory/hook/policy/consent/kernel/cancellation/cleanup
failure or an oversized, malformed, empty or blocked successful model response.

## Remaining scope and decisions

Separate empty-output retry, typed first-token no-progress events, SDK recovery,
shared auxiliary routing/discovery, broader adapters, larger video upload lifecycle
and live acceptance remain open, together with native mobile/inbound media work.
The [source-based routing map](h277-auxiliary-routing-map-2026-10-02.md) identifies
actual non-video consumers for the next shared routing increment; it is not an
implementation or acceptance claim.

Standing owner autonomy and the Sol High writer plan replaced interactive stage
gates; the cost is possible design rework, mitigated by the written contract and
review. Default zero preserves old single-send authority at the cost of requiring
explicit configuration to enable the capability. The inspected asynchronous
primary-only behavior superseded an earlier all-lane/timeout draft; typed fast
first-token timeout recovery remains an explicit gap until native progress events
exist. No accepted requirement is removed from the full goal.
