The new tests distinguish signed-task target binding, post-permit receipt and persisted-payload changes, post-acceptance kernel denial, and remote per-call approval after role consent. They also distinguish descriptor nofollow and per-read resource bounds, chunked HTTP byte bounds, private redirect validation, and URL/method/Authorization/Cookie/direct-transport changes at the physical model request. The private-redirect test uses an offline resolver that maps to a public IP: it shows a forbidden *private URL/Host second request* when validation is removed, not a live socket to a private address.

The `unsigned_intake_allowed` mutation is a **diagnostic contract kill only**. With mediation mode `hold`, removing the explicit enforce check changes the refusal from `signed_video_mediation_required` to `video_proposal_refused`; the mutant still does not enqueue or reach egress. It must not be described as a demonstrated unsigned execution or source/model disclosure.

The two survivors have overlapping current defenses, with limited proof:

- `unsigned_execute_allowed`: Removing the video execution handler's explicit enforce check alone remains blocked in `off` mode because `TaskQueue._classification` returns false; in `hold` mode the worker holds mediated tasks, while the coordinator's trusted execution context separately requires `enforce` for video. All 168 current tests pass with this one mutation. This is a present callgraph observation, not a claim that the check is redundant under every future route.
- `remote_role_consent_ignored`: The video remote policy is currently `unknown`, which produces a warning. `authorize_role_target` refuses a missing acknowledgment before the video policy's outer acknowledgment condition. All 168 current tests pass with the outer condition removed. A future warningless policy or authorizer change could make that condition distinguishable.

The inherited vision route, video-model precedence, exact native-URL key gate, invalid-vision refusal, source and configuration rechecks, no direct-transport substitution, and answer withholding after cleanup are represented by killed mutations. No failure-time provider retry mutation was added; the existing baseline still tests that behavior. OAuth, alternate native provider transports, remote/live acceptance, and full Hermes fallback parity remain outside this campaign.
