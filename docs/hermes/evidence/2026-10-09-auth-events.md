# H512 authentication event audit — local implementation note

Generated: 2026-10-09 UTC. Base: `da7c8a222c2cd0cb658b192c967194bc9c88efa3`. Head at design: same. Branch: `codex/authentication-audit-20261009`.

Goal: record HTTP user/admin guard decisions and managed token issue/rotate/revoke in the existing hash-chained security audit, including offline CLI mutations. A successful token check, denied token check, and unauthenticated direct-localhost allowance must be distinguishable. Audit failure must not change authorization or a committed token mutation.

Non-goals: introduce login, session, refresh, logout, WebSocket ticket, native-app, or OAuth flows; alter guard predicates, error codes, token storage, or rate limiting; record request bodies, URLs, headers, credentials, or user-supplied token labels. The full Hermes 16-event contract is not present in this bearer-token service, so this slice covers only the corresponding token-auth and token-lifecycle events.

Changed paths: `agents/core/orchestrator_bindings.py` updates the exact writer coordinate shifted by guard additions; persona/webhook test assertions distinguish auth telemetry from mutation events; `agents/core/security/types.py` adds lower-case persisted event types; new `agents/core/security/auth_audit.py` owns whitelist-only event construction, sink resolution and bounded best-effort dispatch; `agents/web.py` calls it beside existing guard returns/errors; `agents/core/security/token_store.py` records committed lifecycle mutations including CLI; `agents/core/routers/admin.py` removes its duplicate generic rotation audit; `agents/core/security/audit.py` takes a SQLite write transaction before reading the chain tail to serialize separate CLI/server connections; `tests/test_auth_audit_events.py` pins behavior.

Design: HTTP guards and committed token mutations submit at most 64 pending writes to one daemon audit worker; a full queue drops the new audit row and logs a value-free warning. The worker uses `AuditLogger.log` outside the event loop. Each queued row records trusted submission time, even if the worker is delayed. A queued request captures the active orchestrator sink so a later orchestrator replacement cannot redirect its row; absent an orchestrator, the worker uses the process-wide fallback sink. The daemon can be terminated at process exit with pending rows; the offline CLI waits at most 0.5 seconds for normal writes to finish, then returns even if a sink is stuck. No production shutdown waits without a bound. Token-store mutations commit before enqueuing, so audit failure cannot change the credential result. `AuditLogger.log` locks the SQLite write transaction before reading the tail, so separate connections cannot fork the chain. Values are constructed only from fixed enums, bounded counts and validated IP addresses before enqueue and serialization; unlisted fields are dropped before entering the queue, and no token fingerprint is necessary. `tier` means the guarded route tier, not a verified identity: when both user and admin headers are present the success reason can be generic. Failures log only the exception class, never exception text; a broken warning handler is also swallowed.

Tests: red-first focused user/admin guard 200/401/403 and localhost bypass cases, admin-superset user access, sink and warning failure preserving responses, secret nonappearance in raw audit DB/warnings, issue/rotate/revoke single lifecycle rows and `verify_chain`, subprocess CLI persistence, queue cap, slow-sink token return, queued sink capture, submitted timestamp, and a two-connection concurrent append regression. Focused pytest and Ruff run here; coordinator runs the serial full backend suite.

Rollback: the writers can be reverted without changing credential state or the SQLite schema. Already persisted rows keep their valid hashes, but older readers cannot deserialize the new event types through `AuditLogger.query`. Retain the new enum definitions in any rollback reader while those rows remain, or prepare an explicit compatible data/reader migration before a full code rollback; exporting the rows alone does not make the old reader compatible. No credential rotation is required.

Dependencies: existing `AuditLogger`, `SecurityEvent`, `TokenStore`, and orchestrator `audit` instance; Python stdlib worker primitives. No external provider or credential. Open PR #1233 edits unrelated `agents/web.py` scopes; guard-only edits avoid that overlap.

Remaining contract gap: the original Hermes event set includes login start/success/failure, logout, refresh, session verification, WebSocket tickets, and native-app events. This app does not expose those flows in these bearer guards, so this slice does not claim the full H512 contract or equivalent coverage. Sustained audit outages, a full queue, or CLI timeout followed by process exit can lose rows; the drop warning is rate-limited. No off-box audit shipping is added here.
