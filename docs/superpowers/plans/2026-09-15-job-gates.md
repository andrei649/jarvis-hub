## Constraints and exact semantics

- Existing approved terminal task must finish successfully before interpreting stdout. Failed, rejected, missing or pending tasks retain existing handling.
- Last non-empty stdout line is parsed as JSON; suppress only a dict with `wakeAgent is False`. Missing/invalid JSON, non-dict, false-like numbers/strings/null and true fail open. Inspect the full returned stdout before presentation truncation. If terminal metadata says output was truncated, do not trust a gate: continue normal existing behavior.
- This protocol applies to both script modes. It is the documented exception to otherwise verbatim no_agent output; no_agent text such as `[SILENT]` remains literal output.
- Model silence matching uses whitespace-trimmed, case-insensitive full reply before presentation/notepad caps. `[SILENT]` is recognized as the whole reply or a standalone first/last line. Bracketless `SILENT`, `NO_REPLY`, `NO REPLY` are whole-response variants; do not broaden them to embedded prose or sentences.
- Suppression is a completed successful evaluation, with explicit bounded `Suppressed: wake_gate` or `Suppressed: model_silent` history summary. Script attempt data additionally records suppressed_reason; there is no send, interrupt-budget debit or false failure. Model notepad remains bounded as before.
- Preserve empty script-as-context skipping, per-fire immutable source approval, e-stop, quiet hours, taint fencing, idempotent reconciliation and repeat accounting.
- No monitor, URL fetch, kernel/security/policy changes, dependency changes, global docs/counts, pushes or PRs.
