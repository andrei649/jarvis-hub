# Durable manual job dispatch

Base 02f44a7b. Scope jobs dispatcher/store/router/CLI/HUD and focused tests only. No standing authority grant or frozen-row closure.

Manual POST persists a bounded receipt and returns 202 without invoking effects. Duplicate outstanding requests for one job coalesce atomically. Receipt identity is distinct from eventual JobRun identity; a guarded GET exposes queued/running/waiting/completed/unknown/cancelled state. CLI prints acceptance and receipt lookup; HUD polls it until terminal.

A bounded set of 64 advisory file-lock stripes beside the SQLite database gates all JobRunner.fire calls, cron and manual, across processes. Uses the existing portable vault file-lock abstraction (POSIX flock / Windows msvcrt), with zero timeout. Colliding unrelated jobs defer manual requests and asynchronously serialize cron firings without discarding them; cancellation remains interruptible. OS releases locks after crash; no time lease permits replay. Under the gate, an abandoned running receipt becomes unknown and is never replayed. Unclaimed queued receipts survive restart. The normal fire body and all existing per-effect approvals remain shared. No lock files are deleted while processes could hold them.

Manual requests retain current force=True behavior: paused/disabled jobs can be explicitly triggered; repeat limits and e-stop still apply. Configuration identity (action/options) is frozen at acceptance; changed configuration cancels an unclaimed request. Deleted jobs cancel queued requests. Deletion after execution claim cannot revoke an effect already underway; existing delivery/effect checks remain authoritative. Script approval pending is a waiting receipt linked to the exact existing run row, not completion; reconciliation follows that row without replaying the script.

Completed receipt retention is bounded to 200; outstanding receipts coalesce per job and are bounded by an explicit global capacity. Active linked run evidence must not be pruned by ordinary history retention. Claim and coalescing use SQLite BEGIN IMMEDIATE. Scheduler drain is registered at startup and acceptance, and manual offline tick drains the same queue. No HTTP background tasks or inline execution. Scheduler stopped means truthful queued status until resumed/ticked.
