# H517 named-provider bounded review

I found one actionable status-path defect; the approval/CAS and selection seams otherwise match the frozen contract.

## Finding: selected named STT plus provider-store failure breaks capability status

`agents/core/routers/voice.py:369-370` calls `command_status('stt', provider_id=selected)` before entering the `ProviderStoreError` handler at lines 371-377. For a configured nonempty `voice.stt_command_provider`, `command_status` calls `stored_command` (`agents/core/voice/local_providers.py:992-994`), which calls `provider_store.load` (`:929-932`). If the table/database is unavailable or corrupt, `_read` raises `ProviderStoreError` (`agents/core/voice/provider_store.py:80-101`); this exception escapes `_local_providers_state` and the `/api/voice/capabilities` request instead of returning its advertised `provider_store_error`/unavailable state. Reproducer: set the selector to `studio`, then make the named store unavailable/corrupt and request voice capabilities. The named dispatch correctly fails closed, but the status endpoint fails before its intended error response. Move selected-status resolution into the same guarded store-read section or translate `ProviderStoreError` to a not-ready result while preserving the structured error indicator. No test was run.

## Follow-up: selected-provider store error correction

**Verdict: finding resolved; no new defect in this scoped correction.** `_local_providers_state` now derives selected readiness with `command_ready(..., provider_id=selected, verify_content=False)`, whose named-store error path returns a structured not-ready result, while its catalog read remains inside the `ProviderStoreError` handler (`agents/core/routers/voice.py:369-387`). It also derives STT availability from that selected readiness, preserving store-failure refusal and avoiding a legacy-provider fallback.
