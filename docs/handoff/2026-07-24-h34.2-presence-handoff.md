## 4. Incident de sesiune: eroarea „a lock file already exists in the repository"

La merge-ul lui #726 a apărut o dată eroarea GitHub **„A lock file already exists in the repository, which blocks
this operation from completing."** — un **409 tranzitoriu**: GitHub serializează scrierile pe backend-ul git al
repo-ului, iar un lock rămas pe un ref (ex. `refs/heads/main.lock`) de la o scriere anterioară/în curs (merge, push,
sau conversia draft→ready făcută în aceeași clipă) blochează scrierea următoare. **Nu e corupție și nu e un fișier
din repo** — lock-urile trackuite (`*.lock`, `package-lock.json`, `requirements*.lock`) n-au nicio legătură.

**Rezolvare (a mers la retry):** re-încearcă operația după câteva secunde; nu declanșa două scrieri pe același ref
simultan (draft→ready + merge în aceeași secundă, sau auto-merge care se bate cu un merge manual). Merge-ul a trecut
curat la a doua încercare (`3558920`). Procedura completă (inclusiv ce faci dacă persistă minute în șir) trăiește
acum în **`docs/MAINTENANCE_RUNBOOK.md` §9**.
