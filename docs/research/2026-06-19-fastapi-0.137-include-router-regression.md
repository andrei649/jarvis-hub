# fastapi 0.137 — `app.include_router` route-surface regression (investigation)

**Date:** 2026-06-19 · **Trigger:** Dependabot #237 (`fastapi >=0.137.2,<0.138`) · **Status:** root-caused; upgrade held, remediation specified.

## Symptom
On `fastapi 0.137.x`, CI's route guards fail hard:
```
tests/test_route_parity_guard.py::test_route_surface_size_sanity  → assert 83 >= 290  FAILED
tests/test_route_parity_guard.py::test_route_surface_unchanged    → ~213 routes "REMOVED"
tests/test_route_auth_matrix.py::test_route_guards_match_snapshot  → same ~213 routes "REMOVED"
```
Every route mounted via `app.include_router(...)` (all the CLN-3 per-domain routers in
`agents/core/routers/*` — a2a, kg, memory, canvas, capture, brain, …) disappears from the
counted surface; only the ~83 routes declared inline on `app` in `agents/web.py` survive.

## The app is NOT broken — only static `app.routes` introspection is
Reproduced in isolation (clean venv, trivial app), the routes **still work at runtime**:
```python
# fastapi 0.137.2 (+ any starlette 0.47–1.3)
r = APIRouter(); r.get("/api/foo")(lambda: {"ok": True})
app = FastAPI(); app.include_router(r)

any(getattr(x,"path",None)=="/api/foo" for x in app.routes)   # → False  (!!)
"/api/foo" in app.openapi()["paths"]                          # → True
TestClient(app).get("/api/foo").status_code                   # → 200
```
So routing and OpenAPI are correct; the smoke test (boot + request) would pass. Only code that
**iterates `app.routes` expecting flat `APIRoute` objects** is affected.

## Root cause: the new `_IncludedRouter` wrapper
`fastapi 0.137` changed `APIRouter.include_router` to append **one opaque `_IncludedRouter`
object** to `app.routes` instead of flattening the child routes into it:
```python
app.routes[-1]                       # <fastapi.routing._IncludedRouter>  (path = None)
vars(app.routes[-1]).keys()          # original_router, include_context,
                                     # _effective_candidates, _effective_candidates_version
```
- The child routes live in `…_IncludedRouter.original_router.routes`.
- The include-time `prefix`/`dependencies` live separately in `…include_context`.
- They are merged into `_effective_candidates` **lazily, at request time** (version starts `None`).

`app.openapi()` and the runtime router recurse into `_IncludedRouter`; a naive
`for r in app.routes: if isinstance(r, APIRoute)` loop sees only the wrapper (not an `APIRoute`)
and silently skips everything inside it. **Bisect confirms it is purely a fastapi change**, not
starlette: with starlette held constant at `0.52.1`, `fastapi 0.136.3` works and `0.137.2` does not;
no starlette in `0.47–1.3` rescues `0.137.2`.

> Secondary footgun: `fastapi 0.137` declares `starlette>=0.46.0` with **no upper bound**, so a bare
> install pulls `starlette 1.3.1` (a breaking major). Independent of the `_IncludedRouter` issue,
> any 0.137 adoption should also pin starlette to a tested range.

## Affected code (the only things that break)
Both introspect `app.routes` for flat `APIRoute`s:
- `tests/test_route_parity_guard.py:28-34` — `_route_surface()`: `for r in web.app.routes: if isinstance(r, APIRoute): …`
- `tests/test_route_auth_matrix.py:52-64` — `for r in app.routes:` then walks `r.dependencies`.
- (`tests/test_openapi_parity_guard.py` derives from `app.openapi()`, so it is **already 0.137-safe**.)

No application code is affected — only these test-time guards.

## Remediation (to unblock the upgrade later)
Introduce one shared recursive flattener used by both guards, e.g. `tests/_route_introspect.py`:
```python
def iter_api_routes(app):
    """Yield (path, route) for every APIRoute, descending into 0.137 _IncludedRouter
    wrappers and applying their include_context prefix + dependencies. On <=0.136 there
    are no wrappers, so behavior is identical (pure superset, snapshot-stable)."""
```
- For the **parity** guard, the cleanest source is `app.openapi()["paths"]` (version-stable on
  0.136 and 0.137) — switch `_route_surface()` to it.
- For the **auth-matrix** guard, recurse into `_IncludedRouter.original_router.routes` and fold in
  `include_context` dependencies (openapi can't expose guard `Depends`), guarded by
  `getattr`/`hasattr` so it's a no-op on 0.136.
- Land the flattener **first** (no-op on the pinned 0.136 → green CI), **then** bump
  `fastapi` to `>=0.137.2` **with** a bounded `starlette` pin in the same PR so CI exercises the new path.

## Decision
- **Hold the fastapi bump.** Keep `fastapi>=0.136.3,<0.137` in `requirements*.txt`. #237's harmless
  `pytest-xdist`/`ruff` dev bumps can be taken separately; its fastapi change must not merge until the
  guard flattener lands.
- This file is the record so the upgrade is mechanical when prioritized. Upstream: the `_IncludedRouter`
  change (underscore-private, no migration note for `app.routes` consumers) is worth a fastapi issue.

## Reproduction (for the record)
```
python -m venv v && . v/bin/activate
pip install 'fastapi==0.136.3' 'starlette==0.52.1'   # include_router → /api/foo present  ✅
pip install 'fastapi==0.137.2'                        # include_router → absent from app.routes ❌
                                                      # …but app.openapi() + TestClient still serve it
```
