## 3. Deferred (valuable, but no seam / needs its own slice)

- **`agent/empty_response_guard.py`** (deterministic-empty detection + cost-aware retry budget):
  Nerva's LLM layer has **no empty-retry loop** — the guard would protect a mechanism we don't have.
  Re-open when/if a retry loop lands in `hybrid_router`/`base.py`; the port is then mechanical.
- **`background_review` upstream drift (+749)**: nearly all of it is the cancellation/handshake
  plumbing for their tool-calling background fork. Nerva deliberately re-implemented the distiller
  as a single strict-local structured-output call (H20.L3) — the fork lifecycle does not apply.
  Watch upstream for new *review rules* (those port cleanly); none in this delta.
- **Native/provider compaction** (`native_compaction`, `prompt_cache_boundary/scope`,
  `compaction_display`, most of the compressor's +2,026): built around provider-side prompt caching
  and Anthropic-style native compaction. Nerva is local-first (LM Studio/Ollama hot path); revisit
  for the cloud-opt-in agents (athena) when prompt caching lands in the cloud backends.
- **`cron/monitor.py`, `cron/incidents.py`, `cron/notepad.py`**: overlap Nerva's `heartbeat.py`,
  `argus.py` and the analytics store. The *incident dedup* idea (one incident record per failure
  streak, not one per tick) is worth folding into heartbeat error handling as its own small slice.
- **`agent/deadline.py`** (per-turn wall-clock deadline): interacts with Nerva's iteration budget
  (H20.L1) — port as an extension of `iteration_budget.py`, not a parallel mechanism.
- **`agent/verify/`** (recipes/runner for post-change verification), **`agent/review_engine.py`**:
  candidate for the coach/quality surfaces; needs a design pass against `capability_verification.py`.
- **Loops / heartbeat CLI features** (`hermes_cli/loops.py`, `heartbeat.py` — the new user-facing
  docs): Nerva's heartbeats + autonomy loop already cover the mechanism; the delta is UX (CLI
  ergonomics) which doesn't map to a hub.

## 4. Skipped (anti-thesis — unchanged from the v3 migration plan)

Electron desktop app (`apps/desktop`, ~a third of the diff), the docs website, gateway
browser-control broker + media pipeline, plugin packs/index ecosystem, ACP/OpenAI bridges,
hosted provider breadth (`provider_projection`, model catalog), contributor/email metadata.
Reasons unchanged: local-first, privacy-first, governed autonomy (`MOONSHOT.md` §5); jarvis-hub
is a hub, not a desktop client. Re-open only by explicit owner decision.

## 5. Supply-chain note

Nothing was executed from upstream: the pin regeneration read file bytes from a fresh clone at the
release commit and recorded sha256 digests; the E8.1c posture (`EXECUTION_PROVIDER_E8_1C_PREFLIGHT`)
is unaffected — the Hermes *runtime* remains a rejected/candidate execution seam, not a dependency.
The 11 new pinned skills are import-*available*, not installed; installs still go through the
digest-verified importer and land with provenance `source=hermes`.
