# Gap-fill — Desktop app: Artifacts pager range strip + one orphaned sidebar key (round 1, area desktop-b)

This shard closes two gaps the mechanical string checker found in the Hermes Desktop (Electron/React) renderer.
First, the *left half* of the Artifacts page pagination bar — the "range strip" (`artifacts.zero` / `artifacts.rangeOf`) and the four
`itemLabel` nouns (`artifacts.itemsImage` / `itemsLink` / `itemsFile` / `itemsGeneric`) that follow it and are also spliced into the
numbered-page aria template `artifacts.goToPage`; sibling shards documented only the buttons (`desktop-b.artifacts-page`,
`gapfill-desktop-b-1-r0.shared-pagination`). Second, `sidebar.noWorkspace` — a *dead* i18n key with no consumer left in the tree,
inventoried here as such so the catalogs and the inventory agree.
It deliberately leaves to sibling shards: artifact discovery/extraction, tabs, table columns and open/copy actions
(`desktop-b.artifacts-page`, `desktop-b.artifacts-columns`), the shared Pagination primitive itself
(`gapfill-desktop-b-1-r0.shared-pagination`), the live sidebar project/workspace grouping (`desktop-b.md`, `desktop-a.md`),
and the Cron page delete dialog, whose missing busy label **“Deleting...”** (`i18n: cron.deleting`) was appended in place to
`desktop-b.sidebar-cron-section` rather than duplicated here.

### Artifacts pagination — range strip and item nouns (“0” / “{start}-{end} of {total}” / “images” / “links” / “files” / “items”)  `id: gapfill-desktop-b-r1.artifacts-range-strip`
- **Surface:** Desktop app
- **Where:** Left sidebar nav → **“Artifacts”** (`i18n: sidebar.nav.artifacts`), route `/artifacts`. The strip is the small grey text at the **left end of every pagination bar**: one bar in the sticky 28 px header above the image grid, one in the sticky header above the file/link table. Rendered by `ArtifactsPagination` at `apps/desktop/src/app/artifacts/index.tsx:405-458`; the strip itself is `apps/desktop/src/app/artifacts/index.tsx:421-423`, reading `{pageRangeLabel(total, page, pageSize, a)} {itemLabel}`.
- **What it does:** Tells you how many artifacts the current tab holds and which slice of them you are looking at, e.g. `1-24 of 57 images` or `101-140 of 140 files`; when the section is empty it degrades to the bare **“0”** plus the noun (`0 items`).
- **How it works:** `pageRangeLabel(total, page, pageSize, a)` (`apps/desktop/src/app/artifacts/index.tsx:57-66`) returns `a.zero` — the literal **“0”** in `en` (`apps/desktop/src/i18n/en.ts:2136`) — when `total === 0`; otherwise it computes `start = (page - 1) * pageSize + 1` and `end = Math.min(total, page * pageSize)` and returns `a.rangeOf(start, end, total)`, whose `en` implementation is the template `` `${start}-${end} of ${total}` `` (`apps/desktop/src/i18n/en.ts:2137`, typed `(start: number, end: number, total: number) => string` at `apps/desktop/src/i18n/types.ts:1810`). The noun that follows comes from the caller's `itemLabel` prop: the image pager hard-codes `a.itemsImage` (`index.tsx:362`), the table pager passes `itemsLabel(kindFilter, a)` — the ternary `f === 'link' ? a.itemsLink : f === 'file' ? a.itemsFile : a.itemsGeneric` (`apps/desktop/src/app/artifacts/index.tsx:107-108`). The very same `itemLabel` string is then interpolated into every numbered page button's `aria-label` via `a.goToPage(itemLabel, item)` (`index.tsx:441`; `en` template `` `Go to ${itemLabel} page ${page}` ``, `en.ts:2138`). Page sizes are constants: **24** for the image grid (`index.tsx:362`, slice at `index.tsx:230-233`) and **100** for the table (`index.tsx:369`, slice at `index.tsx:235-238`); `pageCount = Math.max(1, Math.ceil(total / pageSize))` (`index.tsx:415`), and `currentImagePage` / `currentFilePage` clamp the stored page with `Math.min(page, pageCount)` (`index.tsx:227-228`). All values are derived in-memory from the already-loaded `visibleImageArtifacts` / `visibleFileArtifacts` arrays — no request is made when you page. Markup: `<div className="shrink-0 text-[0.62rem] text-muted-foreground">` inside the `flex h-6 items-center justify-between gap-2 px-1` pager row; the strip is `justify-between`'s left child, the `<Pagination>` nav its right child.
- **Inputs / options:** Not clickable — the strip is static text. Its content is driven by: the active tab (`?tab=all|image|file|link`, `useRouteEnumParam('tab', ARTIFACT_FILTERS, 'all')`), the search query (filters `total` before it is counted), and the current page (Prev / Next / numbered buttons). Verbatim strings it can print: **“0”** (`i18n: artifacts.zero`); **“{start}-{end} of {total}”** (`i18n: artifacts.rangeOf`) — e.g. “1-24 of 57”, “25-48 of 57”, “1-1 of 1”. Verbatim nouns appended after it: **“images”** (`i18n: artifacts.itemsImage`) for the image-grid pager on every tab that shows images; **“links”** (`i18n: artifacts.itemsLink`) for the table pager when the tab filter is `link`; **“files”** (`i18n: artifacts.itemsFile`) when the filter is `file`; **“items”** (`i18n: artifacts.itemsGeneric`) as the fallback on the **“All”** tab and any non-`link`/non-`file` filter. Resulting aria on the numbered buttons (`i18n: artifacts.goToPage`): **“Go to images page 2”**, **“Go to links page 2”**, **“Go to files page 2”**, **“Go to items page 2”**.
- **Outputs / side effects:** Pure render — no disk, no network, no state. It re-renders when `onPageChange` moves the page atom (`setImagePage` / `setFilePage`, `index.tsx:126-127`) or when the filtered artifact list changes.
- **Config / env:** n/a — page sizes are literals in the component, not config keys. Locale comes from the app language setting consumed by `useI18n()`.
- **Edge cases / guards:** With `total === 0` the surrounding `<section>` is not rendered at all (`index.tsx:359`, `index.tsx:382` guard on `.length > 0`), so **“0”** is effectively unreachable in the shipped page and exists as a defensive branch; the whole page instead shows **“No artifacts found”** (`i18n: artifacts.noArtifactsTitle`). The buttons half of the bar is hidden when `pageCount > 1` is false, but the range strip still renders — a single-page section shows `1-7 of 7 items` with no buttons. `end` is clamped by `Math.min(total, page * pageSize)` so the last page never over-reports. The nouns are *not* pluralised by count: `1-1 of 1 images` is possible. In RTL (`ar`) the strip flows right-to-left and `zero` is the word **“صفر”** rather than a digit (`apps/desktop/src/i18n/ar.ts:1641`); `zh` / `zh-hant` / `ja` keep `'0'` and reorder the template (`zh`: `` `${start}-${end}，共 ${total}` ``, `ja`: `` `${total} 件中 ${start}-${end}` ``) while their nouns carry the CJK measure word (`zh` `'张图片' / '个链接' / '个文件' / '项'`, `zh-hant` `'張圖片' / '個連結' / '個檔案' / '項'`, `ja` `'画像' / 'リンク' / 'ファイル' / '項目'`, `ar` `'صور' / 'روابط' / 'ملفات' / 'عناصر'`).
- **Rebuild notes:** Minimum: a `justify-between` row whose left child is `total === 0 ? "0" : "{start}-{end} of {total}"` followed by a caller-supplied noun, with `start = (page-1)*size+1`, `end = min(total, page*size)`, and the same noun reused inside the page buttons' `aria-label`. A better version would pluralise the noun against the count (ICU `plural`), make the range a live region announced on page change, expose a page-size selector, and hide the "of N" when a single page fits — plus derive the count from a backend index so the strip can show the true total instead of "of what we managed to scan".

### Chat sidebar — “No workspace” group label (orphaned i18n key)  `id: gapfill-desktop-b-r1.sidebar-no-workspace`
- **Surface:** Desktop app
- **Where:** No live surface in v2026.8.31. The string **“No workspace”** exists only in the i18n catalogs — `apps/desktop/src/i18n/en.ts:2198` (`sidebar.noWorkspace`), declared in the contract at `apps/desktop/src/i18n/types.ts:1865`, and translated in `apps/desktop/src/i18n/zh.ts:2379` (`'无工作区'`), `apps/desktop/src/i18n/zh-hant.ts:1820` (`'無工作區'`), `apps/desktop/src/i18n/ja.ts:1884` (`'ワークスペースなし'`), `apps/desktop/src/i18n/ar.ts:1705` (`'بدون مساحة عمل'`). A repo-wide grep for `noWorkspace` across `apps/desktop/src` and `web/src` hits only those six files — there is no `s.noWorkspace` / `t.sidebar.noWorkspace` reader left.
- **What it does:** Historically it named the synthetic sidebar group that collected every chat whose session row had no workspace/`cwd` (desktop-launched chats, whose accidental launch directory the backend deliberately stores as `NULL`). Today nothing renders it.
- **How it works:** Until commit `488ae376db` “feat(desktop): render backend-authoritative projects sidebar” (2026-06-25) the sidebar grouped client-side: `workspaceTreeFor(agentSessions, s.noWorkspace, worktreeResolver)` / `workspaceGroupsFor(sessions, noWorkspaceLabel)` bucketed sessions by `session.cwd?.trim()`, using the constant id `'__no_workspace__'` and `label = baseName(path) || path || noWorkspaceLabel` for the empty bucket, with `path: null` so `disambiguateLabels()` skipped it ("the synthetic 'No workspace' group has no path and stays as-is"; a unit test asserted it "keeps the synthetic no-workspace group untouched even if a real group shares its label"). That commit deleted `workspace-groups.ts` and moved grouping to the gateway's projects RPC; the no-project bucket is now flagged `project.isNoProject` and rendered with **“Home”** (`i18n: sidebar.projects.home`) — see `apps/desktop/src/app/chat/sidebar/index.tsx:915`, `apps/desktop/src/app/chat/sidebar/filter-menu.tsx:361`, `apps/desktop/src/app/chat/sidebar/session-row.tsx:272`. The backend half of that behaviour survives and still calls the bucket "No workspace" in its own comments and tests: `_persisted_session_cwd({"source": "desktop", ...}) is None` because “an unpicked cwd is an artifact — those chats belong under ‘No workspace’” (`tests/tui_gateway/test_projects_rpc.py:489-493`, `tests/test_tui_gateway_server.py:7663-7683`).
- **Inputs / options:** n/a — no control, no shortcut, no argument. The sibling keys in the same `sidebar` block that *are* live: **“Ungroup sessions”** (`i18n: sidebar.groupTitleGrouped`), **“Group by workspace”** (`i18n: sidebar.groupTitleUngrouped`), **“Show sessions as a single list”** (`i18n: sidebar.groupAriaGrouped`), **“Group sessions by workspace”** (`i18n: sidebar.groupAriaUngrouped`), **“Everything here is pinned. Unpin a chat to show it in recents.”** (`i18n: sidebar.allPinned`), **“No sessions yet”** (`i18n: sidebar.projectEmpty` and `i18n: sidebar.noSessions`), **“No sessions match these filters”** (`i18n: sidebar.noFilterMatches`) — the last four are the empty-state branch at `apps/desktop/src/app/chat/sidebar/index.tsx:1683-1690`.
- **Outputs / side effects:** None. The key is loaded into the translation object like every other, costs a few bytes per locale bundle, and is type-checked by `Translations` so removing it from one locale would break the build — which is why all five locales still carry it.
- **Config / env:** n/a
- **Edge cases / guards:** Because `types.ts:1865` still declares `noWorkspace: string`, the key cannot be dropped from a single locale — it must be removed from `types.ts` and all five catalogs together. Any translation QA pass that diffs catalogs against rendered UI will report this string as untested/unreachable. A future re-introduction of client-side workspace grouping would reuse it, so it is dead code rather than a bug.
- **Rebuild notes:** Minimum for a reimplementation of the original behaviour: bucket sessions by trimmed `cwd`, key the empty bucket with a constant sentinel id, label it from a translated string, and exclude it from any basename-disambiguation pass since it has no path. A better version keeps grouping authoritative on the backend (as this build now does) and adds a lint/CI check that fails on i18n keys with zero consumers, so an orphan like this is deleted with the code that used it.
