# Gap-fill — Hermes Desktop Settings: Language, Appearance rows, Notifications, Plugins (round 0, area `desktop-settings-0`)

Scope: the Hermes Desktop (Electron renderer) **Settings** surfaces that the main `desktop-settings.md` shard did not
reach — the reusable **Language switcher** control, the hand-written **Settings → Appearance** rows that are *not*
schema-driven config fields (Language, Tool Call Display, Collapse thinking by default, Session List Density, Tab Strip,
Terminal Font, Window Translucency), the whole **Settings → Notifications** page (native OS notification preferences +
completion-sound picker), the whole **Settings → Plugins** page (desktop plugins + agent plugins), the **Install plugin**
modal, and the orphan `settings.searchPlaceholder.*` string catalog.
Deliberately left to sibling shards: the schema-driven config fields and the Settings frame/nav/search machinery
(`desktop-settings.md`), the Electron main-process notification/translucency bridges (`desktop-main.md`), the in-app toast
feed (`gapfill-desktop-a-r0.md`), the CLI `hermes plugins …` group (`cli-e.md`), and the Web dashboard's own language
picker (`web-shell.md`).

### Language switcher (globe button + language list)  `id: gapfill-desktop-settings-0-r0.language-switcher`
- **Surface:** Desktop app
- **Where:** The reusable `<LanguageSwitcher />` control. It renders a small outline button showing a globe icon plus the current language's endonym (e.g. `English`, `简体中文`, `繁體中文`, `日本語`, `العربية`) and a chevron; its accessible name is the sheet/popover title `"Switch language"` (`i18n: language.switchTo`). Mounted today in **Settings → Appearance → "Language"** row (`appearance-settings.tsx:461`). On a mobile-width viewport with `dropUp`, it opens a bottom sheet whose header is `"Switch language"` with the description `"Choose the language for the desktop interface."` (`i18n: language.description`); otherwise it opens a 14rem popover.
- **What it does:** Lets the user pick the desktop UI language; the choice is written to the backend config key `display.language` and re-renders every string immediately (including document `lang`/`dir` for RTL).
- **How it works:** `apps/desktop/src/components/language-switcher.tsx:31-118` renders the trigger and chooses sheet vs popover (`useIsMobile()` + the `dropUp` prop, `:34-35`). The list is `LanguageCommand` (`:120-174`): a cmdk `<Command shouldFilter={false}>` with a manual substring filter (`:139-145`) that matches the endonym `meta.name`, the hidden `meta.englishName`, or the locale code, so `"日本"`, `"japanese"` and `"ja"` all find Japanese while preserving the curated order `en → zh → zh-hant → ja → ar` (`i18n/languages.ts:7-38`). Each row shows a check (visible only for the active locale), the endonym, and the uppercase mono locale code. Selecting calls `selectLocale` (`:40-56`): no-op when already selected or a save is in flight, `triggerHaptic('selection')`, then `await setLocale(code)` from `useI18n()`; success closes the popover and fires `triggerHaptic('success')`, failure calls `notifyError(error, t.language.saveError)`. `setLocale` lives in `apps/desktop/src/i18n/context.tsx:115-147`: it optimistically sets the locale, flips `isSavingLocale` true, re-reads the latest config (`getHermesConfigRecord()`), writes `display.language = localeConfigValue(locale)` via `withConfigDisplayLanguage` (`context.tsx:42-52`) and `saveHermesConfig`, and on failure ROLLS BACK to the previous locale and rethrows. On locale change an effect sets `setRuntimeI18nLocale(locale)` (so plugin `ctx.i18n.t` follows) and `applyDocumentLocale(locale)`; `RTL_LOCALES = new Set(['ar'])` (`context.tsx:58`). Locale normalisation/aliasing is `normalizeLocale` over `LOCALE_ALIASES` (`languages.ts:48-95`, covering `en-us`, `zh-cn`, `zh-hans`, `zh-tw`, `zh-hk`, `zh-mo`, `zh-hant-tw`, `zh-hant-hk`, `ja-jp`, `ar-sa`, `ar-ae`, `ar-eg`, `arabic`, `العربية`, …), defaulting to `en`.
- **Inputs / options:** Props `className`, `collapsed` (hides the label + chevron, icon only), `dropUp` (opens upward; with a mobile viewport switches to the bottom sheet). Controls: the trigger button (`aria-label` = `"Switch language"`, `aria-expanded`, disabled while `isSavingLocale`); search input placeholder `"Search languages…"` (`i18n: language.searchPlaceholder`, used by both the sheet variant `:95` and the popover variant `:113`); one selectable row per locale — `English` (`en`), `简体中文` (`zh`), `繁體中文` (`zh-hant`), `日本語` (`ja`), `العربية` (`ar`); the empty state `"No languages found"` (`i18n: language.noResults`) when the filter matches nothing; sheet header title `"Switch language"` and sheet description `"Choose the language for the desktop interface."`.
- **Outputs / side effects:** Writes `display.language` into the backend config file (`~/.hermes/config.json` for the active profile) through `saveHermesConfig`; sets `document.documentElement.lang` and `dir`; publishes the runtime locale to plugins; on failure raises the error toast titled `"Language update failed"` (`i18n: language.saveError`).
- **Config / env:** `display.language` (values `en`, `zh`, `zh-hant`, `ja`, `ar`).
- **Edge cases / guards:** Every control is disabled while `isSavingLocale`. A failed save rolls the UI back to the previous locale before rethrowing, so the picker never lies about what is persisted. cmdk's built-in fuzzy filter is explicitly disabled because its scoring re-sorts the curated order. No country flags are used — deliberately, because languages are not countries (`languages.ts:40-43`). Without a desktop bridge (`window.hermesDesktop.api` absent) the config client resolves to a no-op that reports `{ ok: true }`, so the picker still switches the in-memory locale in web/test shells.
- **Rebuild notes:** Endonym-first list + hidden English name for search + locale code as the value; optimistic set, persist, roll back on failure, and disable the whole control while saving. A better version would offer the OS locale as an "Auto" row and lazily fetch catalogs so shipping 30 languages doesn't grow the bundle.

### Settings → Appearance → "Language" row  `id: gapfill-desktop-settings-0-r0.appearance-language-row`

- **How it works:** `apps/desktop/src/app/settings/appearance-settings.tsx:460-465` — a `ListRow` whose `description` is `isSavingLocale ? t.language.saving : t.language.description` (`:462`), `title` is `t.language.label` (`:464`) and `id` is `appearanceSettingElementId(APPEARANCE_SETTING_IDS.language)` → DOM id `setting-field-appearance.language` (`:107`, `settings-search.ts:13-22`). `isSavingLocale` comes from `useI18n()` (`:347`). The row is a deep-link target: `useDeepLinkHighlight({ elementId: appearanceSettingElementId, param: 'setting', ready: id => APPEARANCE_SEARCH_TARGETS.has(id) })` (`:393-397`) scrolls to and highlights it for `/settings?tab=config:appearance&setting=appearance.language`. The same copy backs the settings-search/palette entry: `use-settings-search.ts:113-121` builds `{ id: 'setting:appearance.language', label: t.language.label, description: t.language.description, keywords: ['locale'], context: t.settings.sections.appearance, icon: Palette }`.
- **Inputs / options:** One control — the language switcher button (see `gapfill-desktop-settings-0-r0.language-switcher` for its full input list). No flags of its own.
- **Outputs / side effects:** None beyond the switcher's (`display.language` write). Visible side effect: the description text swaps to `"Saving language…"` for the duration of the save.
- **Config / env:** `display.language`.
- **Edge cases / guards:** The row renders even when the config record has not loaded — the switcher shows the default `English` until the config resolves and `normalizeLocale(getConfigDisplayLanguage(config))` replaces it.
- **Rebuild notes:** Bind the row description to the save state rather than adding a spinner; it costs one ternary and reads better. A better version would also show the locale's coverage ("94% translated") so users know what to expect.

### Settings → Appearance → "Terminal Font"  `id: gapfill-desktop-settings-0-r0.appearance-terminal-font`
- **Surface:** Desktop app / Config
- **Where:** **Settings → Appearance**, wide row titled `"Terminal Font"` (`i18n: settings.appearance.terminalFontTitle`) with description `"Choose an installed font for Desktop terminals. Nerd Fonts render Powerlevel10k and shell icons; leave blank to use bundled JetBrains Mono."` (`i18n: settings.appearance.terminalFontDesc`). Below it: a text input with placeholder `"MesloLGS NF or a CSS font stack"` (`i18n: settings.appearance.terminalFontPlaceholder`), a `"Use default"` text button (`i18n: settings.appearance.terminalFontReset`), and a live sample line labelled `"Glyph preview"` (`i18n: settings.appearance.terminalFontPreview`) followed by the literal sample text ` ~/project git:main ❯`.
- **What it does:** Sets the font family used by every Desktop terminal pane, with an autocomplete of known Nerd Fonts and an instant glyph preview so the user can see whether their font renders Powerline/Nerd glyphs.
- **How it works:** `apps/desktop/src/app/settings/terminal-font-setting.tsx`. The value is the backend config key `terminal.font_family`, read via `useHermesConfigRecord()` and `getNested(config, 'terminal.font_family')` normalised by `normalizeTerminalFontFamily` (`:24-26`). Local `draft` state seeds once per profile (`:49-57`); `useOnProfileSwitch` (`:59-66`) resets `draft` to `null`, records the stale config object so the previous profile's cache cannot re-seed, and clears the live font. Every keystroke calls `update(value)` (`:119-124`): bumps `saveVersionRef`, sets the draft, and applies `setTerminalFontFamilyFromConfig(value)` so terminals repaint instantly. A debounced autosave (`AUTOSAVE_DELAY_MS = 550`, `:22`, effect `:68-117`) writes `setNested(loadedConfig, 'terminal.font_family', value)` through `saveHermesConfig`; success updates the shared config cache via `setHermesConfigCache(next)`, failure cancels the pending save, rolls the draft and the live font back to the last persisted value and raises `notifyError(error, t.settings.config.autosaveFailed)`. The input is backed by `<datalist id="hermes-terminal-font-families">` populated from `TERMINAL_FONT_SUGGESTIONS` (`app/right-sidebar/terminal/terminal-font`). The preview `<div>` carries `aria-label="Glyph preview"` and `style={{ fontFamily: resolveTerminalFontFamily(value) }}` (`:152-161`). Mounted from `appearance-settings.tsx:584`.
- **Inputs / options:** (1) Font family text input — `aria-label` `"Terminal Font"`, placeholder `"MesloLGS NF or a CSS font stack"`, `spellCheck` off via the `Input` primitive, `list="hermes-terminal-font-families"` datalist suggestions, disabled while `draft === null` (config not yet loaded for this profile). (2) `"Use default"` button — clears the field (`update('')`), disabled when the field is already empty or the config has not loaded. (3) The read-only preview area labelled `"Glyph preview"` rendering ` ~/project git:main ❯` in the resolved stack.
- **Outputs / side effects:** Persists `terminal.font_family` in the backend config for the active profile (debounced 550 ms); repaints terminals immediately; on a save failure shows the autosave-failed error toast and reverts.
- **Config / env:** `terminal.font_family` (empty string = bundled JetBrains Mono).
- **Edge cases / guards:** A profile switch blanks the field rather than showing the previous profile's font; the seed effect refuses to re-seed from the recorded stale config object. The save effect exits early when the normalised draft already equals the persisted value, which also terminates the re-run triggered by the cache write. In-flight saves are versioned (`saveVersionRef`) so a stale response cannot clobber a newer edit.
- **Rebuild notes:** Debounced autosave + version token + rollback-to-cache is the whole pattern; the preview must use the *resolved* stack (user value plus fallbacks), not the raw input. Better: enumerate installed system fonts (`queryLocalFonts`) and flag stacks with no Nerd-Font glyph coverage.

### Settings → Appearance → "Window Translucency"  `id: gapfill-desktop-settings-0-r0.appearance-translucency`
- **Surface:** Desktop app
- **Where:** **Settings → Appearance**, row titled `"Window Translucency"` (`i18n: settings.appearance.translucencyTitle`). Description in Clear mode: `"See your desktop through the whole window, text and all. Tuned separately for light and dark."` (`i18n: settings.appearance.translucencyDesc`); in Glass mode: `"Matte glass: the desktop shows through as a smooth blur while text stays sharp. Tuned separately for light and dark."` (`i18n: settings.appearance.translucencyGlassDesc`). The row is **absent on Linux**.
- **What it does:** Chooses how much of the desktop shows through the Hermes window, in one of two modes — `Clear` (whole-window opacity) or `Glass` (native material blur with sharp text) — and, in Glass mode, exposes Tint, Fade, Frost and Area sub-controls.
- **How it works:** `appearance-settings.tsx:616-698`. The whole row is wrapped in `{TRANSLUCENCY_SUPPORTED && …}` (`:618`) — Linux has neither `setOpacity` nor a native material, so the row is not rendered rather than offering a dead lever. The action area (`data-translucency-peek-scope=""`, `:626`) holds the mode `SegmentedControl` (only when `GLASS_SUPPORTED`) with options `{ id: 'clear', label: a.translucencyModeClear }` and `{ id: 'glass', label: a.translucencyModeGlass }` (`:631-634`); in Clear mode a single `TranslucencySlider` labelled `"Window Translucency"` sits beside it (`:642-648`). In Glass mode four labelled `GlassRow`s render below (`:652-691`). `TranslucencySlider` (`:296-327`) is an `<input type="range">` with `min={TRANSLUCENCY_MIN}` = 0, `max={TRANSLUCENCY_MAX}` = 100, `step={TRANSLUCENCY_STEP}` = 1 (`apps/shared/src/translucency.ts:195-199`), `aria-label` = the row label, `accentColor: var(--dt-primary)`, a trailing `NN%` readout, and peek wiring: `onPointerDown={beginTranslucencyPeek}`, `onPointerUp`/`onLostPointerCapture`/`onBlur={endTranslucencyPeek}`, and `pulseTranslucencyPeek()` on arrow-key steps. Every segmented pick goes through `pickTranslucency(setter)` (`:380-389`) which haptics, applies, and pulses the peek when intensity > 0. Frost options come from `glassMaterialsFor(GLASS_IS_WINDOWS)` labelled by `a.translucencyFrost[material]` (`:674-677`) — `GLASS_MATERIALS = ['under-window', 'popover', 'titlebar', 'header']` (`apps/shared/src/translucency.ts:39`); Windows collapses the ladder to three because `titlebar` and `header` both map to `mica` (`:74-90`), and `glassMaterialForPicker` highlights the rung that renders the same backdrop for a frost saved on a Mac. Area options come from `GLASS_SCOPES = ['window', 'sidebar']` (`:51`). State is the per-appearance `TranslucencyBook` in `localStorage["hermes.desktop.translucency.v2"]` (seeded from `…v1`), resolved for the painted appearance by `$translucency` (`store/translucency.ts:93-109`); defaults are mac light `{intensity: 66, fade: 1, material: 'header', scope: 'window'}`, mac dark `{22, 0, 'titlebar', 'window'}`, Windows light `{20, 0, 'under-window', 'window'}`, Windows dark `{5, 0, 'under-window', 'window'}` (`apps/shared/src/translucency.ts:155-164`). The resolved state is mirrored to the Electron main process, which applies vibrancy/backdrop/opacity (see `desktop-main.translucency`). Row DOM id `setting-field-appearance.translucency` (`:695`).
- **Inputs / options:** (1) Mode segmented control — `"Clear"` (`i18n: settings.appearance.translucencyModeClear`), `"Glass"` (`i18n: settings.appearance.translucencyModeGlass`); shown only when `GLASS_SUPPORTED`. (2) Clear mode: one 0–100 slider labelled `"Window Translucency"` with a `NN%` readout. (3) Glass mode, four rows: `"Tint"` (`i18n: settings.appearance.translucencyTintTitle`) → 0–100 slider; `"Fade"` (`i18n: settings.appearance.translucencyFadeTitle`) → 0–100 slider (native window opacity, default 0 because fading glass fades its text); `"Frost"` (`i18n: settings.appearance.translucencyFrostTitle`) → segmented control with `"Deep"` (`under-window`, `i18n: settings.appearance.translucencyFrost.under-window`), `"Soft"` (`popover`, `i18n: settings.appearance.translucencyFrost.popover`), `"Bright"` (`titlebar`, `i18n: settings.appearance.translucencyFrost.titlebar`) and `"Glare"` (`header`, `i18n: settings.appearance.translucencyFrost.header`) — Windows shows only the first three distinct rungs; `"Area"` (`i18n: settings.appearance.translucencyScopeTitle`) → `"Whole window"` (`i18n: settings.appearance.translucencyScope.window`) / `"Sidebar only"` (`i18n: settings.appearance.translucencyScope.sidebar`). Keyboard: arrow keys step a slider by 1 and pulse the peek.
- **Outputs / side effects:** Writes `localStorage["hermes.desktop.translucency.v2"]`; sends the resolved state over IPC (`hermes:translucency`) so the main process sets vibrancy / `setBackgroundMaterial` / `setOpacity`; while dragging, the overlay "peeks" (field surfaces temporarily ghost so the user can see the change through the Settings sheet).
- **Config / env:** n/a — renderer-local plus `<userData>/translucency.json` on the main-process side.
- **Edge cases / guards:** Hidden on Linux (`TRANSLUCENCY_SUPPORTED`). Glass mode itself is gated by `GLASS_SUPPORTED` (macOS, or Windows 11 build ≥ 22621 — `WINDOWS_GLASS_MIN_BUILD`); on an unsupported OS the mode picker is not rendered and the value normalises back to `clear`. Settings are stored per light/dark appearance, because a tint that whispers on a dark palette is a milky sheet on a light one. The peek is scoped to the overlay the row lives in via `data-translucency-peek-scope` so no other overlay pays for the transition.
- **Rebuild notes:** One 0–100 lever per appearance, one mode, and a total frost→platform-material mapping whose *picker* drops duplicates; peek while dragging or the user cannot see what they are tuning. Better: live per-monitor preview and an "auto-dim when unfocused" rule.

### Settings per-tab search placeholder catalog (`settings.searchPlaceholder.*`)  `id: gapfill-desktop-settings-0-r0.settings-search-placeholder-catalog`
- **Surface:** Desktop app / Docs
- **Where:** `apps/desktop/src/i18n/en.ts:524-531` (and the parallel `zh.ts:511`, `zh-hant.ts`, `ja.ts`, `ar.ts` blocks). A per-tab map of search/header placeholder strings for the Settings overlay, keyed by Settings tab id.
- **What it does:** Declares one placeholder string per Settings tab. In v2026.8.31 the catalog is **defined but has no reader** inside `apps/desktop/src` — every live search box in Settings uses its own key (`t.settings.connections.searchPlaceholder`, `t.settings.appearance.pet.searchPlaceholder`, `t.settings.config.searchPlaceholder`, `t.settings.plugins.agent.search`, `t.language.searchPlaceholder`, `t.settings.search.placeholder`). Treat it as a legacy/lookup catalog kept for translation parity (and reachable dynamically by tab id, e.g. `t.settings.searchPlaceholder[tab]`).
- **How it works:** A flat object literal on the `settings` node of the translation record; typed by `apps/desktop/src/i18n/types.ts` so every locale must supply all six keys. A grep over `apps/desktop/src` for `searchPlaceholder` (48 hits) resolves each hit to a different namespace — none index `t.settings.searchPlaceholder`.
- **Inputs / options:** Six entries: `about` = `"About Hermes Desktop"` (`i18n: settings.searchPlaceholder.about`); `config` = `"Search settings..."` (`i18n: settings.searchPlaceholder.config`); `gateway` = `"Gateway connection..."` (`i18n: settings.searchPlaceholder.gateway`); `keys` = `"Search API keys..."` (`i18n: settings.searchPlaceholder.keys`); `mcp` = `"Search MCP servers..."` (`i18n: settings.searchPlaceholder.mcp`); `sessions` = `"Search archived sessions..."` (`i18n: settings.searchPlaceholder.sessions`). The keys correspond to Settings tabs `about`, the schema-driven `config:*` sections, `gateway` (Gateways), `keys` (Tools & Keys), `mcp` (the legacy MCP tab, now redirected to Capabilities) and `sessions` (Archived Chats) — see `apps/desktop/src/app/settings/types.ts:7-15` and the nav labels in `settings.nav`.
- **Outputs / side effects:** None at runtime today (no reader). Ships in every locale bundle.
- **Config / env:** n/a.
- **Edge cases / guards:** Because the type demands all six keys in every locale, translators keep translating strings nothing renders; a mechanical UI-string checker will flag them as "unused" rather than "missing".
- **Rebuild notes:** Either wire the overlay's per-tab search box to `t.settings.searchPlaceholder[activeTab]` (which is clearly the original intent) or delete the node; keeping an unreferenced catalog costs translation budget every release. Better: derive the placeholder from the tab descriptor so adding a tab cannot forget its placeholder.
