# Gap-fill (round 0, area "desktop-a") — boot-failure recovery overlay, toast/notification stack, Send diagnostics

This shard closes the round-0 coverage gaps for three always-mounted Hermes Desktop renderer surfaces that no sibling
shard documented as features: the full-screen **boot-failure recovery overlay** (`BootFailureOverlay`, all four
variants and every button/hint/toast it can show), the **toast / notification stack** (`NotificationStack`, its two
placements, the expander/clear-all chrome, the per-toast Details disclosure and its Copy detail control) together with
the **error-summarizer table** in `store/notifications.ts` that rewrites raw provider/gateway errors into friendly
one-liners, and the **Send diagnostics to Nous** consent dialog (`SendDiagnosticsHost`) with its three phases.
Deliberately left to siblings: the main-process boot classification/latching that *feeds* this overlay
(`desktop-main.boot-failure-latch`), the renderer boot lifecycle and its non-fatal boot toasts
(`desktop-b.gateway-boot`), the full Settings → Gateway panel that this overlay embeds (`desktop-settings.*`),
the assistant error card that launches Send diagnostics (`desktop-b` error-card entry), native OS notifications
(`desktop-main.notifications`), and the backend `diagnostics.share_nous` RPC (`tui.md`).

### Boot-failure recovery overlay  `id: gapfill-desktop-a-r0.boot-failure-overlay`
- **Surface:** Desktop app
- **Where:** Full-screen modal that masks the whole app whenever the desktop cannot bring up a Hermes backend. Mounted unconditionally beside the other global overlays in `apps/desktop/src/app/contrib/wiring.tsx:1167` (`<BootFailureOverlay />`, immediately after `<GatewayConnectingOverlay />`). Headline is one of three verbatim strings depending on the failure kind: **"Hermes couldn't start"** (`i18n: boot.failure.title`), **"Remote gateway sign-in required"** (`i18n: boot.failure.remoteTitle`) or **"Nous Cloud agent is down"** (`i18n: boot.failure.cloudDownTitle`) — `apps/desktop/src/components/boot-failure-overlay.tsx:384`.
- **What it does:** Turns a hard boot failure (gateway never came up, backend exited during startup, bootstrap latched, remote session expired, Nous Cloud agent 5xx) into an actionable recovery screen instead of a dead shell with a single toast. It shows the failure text, a failure-shaped set of recovery buttons, a hint line, and an optional tail of the backend log.
- **How it works:** `BootFailureOverlay()` (`apps/desktop/src/components/boot-failure-overlay.tsx:46`) reads `$desktopBoot` (`apps/desktop/src/store/boot.ts:21`) and `$desktopOnboarding`. It renders when `visible = Boolean(boot.error) && !boot.running` (`:63`) and is **suppressed** while first-run onboarding owns the flow (`onboarding.flow.status !== 'idle' && !== 'error'`, `:67`). Two effects run when it becomes visible: (1) `window.hermesDesktop.getRecentLogs()` → `setLogs(res.lines ?? [])` (`:74-77`); (2) `getConnectionConfig()` → `setConnectionConfig`, `setRemoteFailure(isRemoteConfig(config))`, and — when `isRemoteReauthFailure(config, boot.error)` — a best-effort `probeConnectionConfig(config.remoteUrl)` whose `providers` are folded through `deriveProviderShape` into `setRemoteReauth({url, isPassword, providerLabel})` (`:95-136`). Branch selection at `:284-341`: `remoteReauth` → reauth action set; else `cloudDown = Boolean(boot.isCloudBackendDown)` (`:282`, structured flag forwarded by the main process, `global.d.ts:1095`) → cloud-outage action set; else `remoteFailure` → remote action set; else the local action set. The error body text runs through `sshFailureMessage(connectionConfig, boot.error, t.settings.gateway)` (`:394`, helper at `apps/desktop/src/components/boot-failure-reauth.ts:80`), which for `mode === 'ssh'` maps the raw error onto the Gateway panel's SSH copy — **"The host key has CHANGED since you last connected. Verify this is expected, then run ssh-keygen -R <host> and reconnect."**, **"SSH authentication failed. Load your key into the ssh-agent (ssh-add) or set an IdentityFile in ~/.ssh/config — Hermes runs ssh non-interactively."**, **"Hermes is not installed on the remote host. Install it there (curl -fsSL https://hermes-agent.nousresearch.com/install.sh | sh) or set the Hermes path."**, **"Unsupported remote platform. Hermes Desktop SSH mode supports Linux, macOS, and Windows remote hosts."**, **"SSH connection timed out. The host may be unreachable or asleep."**, **"Update Hermes on the remote host before connecting with Desktop SSH."**, **"Could not reach that host over SSH. Check the host, port, and your network."**, **"SSH connection failed."** (`i18n: settings.gateway.sshErrHostKey / sshErrAuth / sshErrNotInstalled / sshErrPlatform / sshErrTimeout / sshErrUpdateRequired / sshErrUnreachable / sshErrUnknown`, `apps/desktop/src/i18n/en.ts:969-980`); any non-SSH mode shows the raw error string. Layout: `fixed inset-0 z-(--z-setup)` with `data-glass-opaque=""` so window glass never lets the app show through (`:374-377`), a `max-w-[40rem]` card, an `ErrorIcon`, headline `h2`, description `p`, then a destructive-tinted error box, the button row, the hint, and the log disclosure.
- **Inputs / options:** Every control the overlay can render, grouped by variant. **Always present:** **"Open logs"** (`i18n: boot.failure.openLogs`, `FileText` icon, `variant="ghost"`, appended after the variant actions, `:405-408`) → `window.hermesDesktop.revealLogs()`. **Local-failure set (default):** **"Retry"** (`boot.failure.retry`, `RefreshCw`, busy key `retry`), **"Repair install"** (`boot.failure.repairInstall`, `Wrench`, `variant="secondary"`, busy key `repair`), **"Gateway settings"** (`boot.failure.gatewaySettings`, `SlidersHorizontal`, `variant="ghost"`); hint **"Repair re-runs the installer and can take a few minutes on a fresh machine."** (`boot.failure.repairHint`). **Remote-failure set:** **"Gateway settings"** (primary), **"Retry"** (`variant="secondary"`), **"Use local gateway"** (`boot.failure.useLocalGateway`, `variant="secondary"`, busy key `local`); hint **"Check the gateway URL and sign-in under Gateway settings, or switch to the local gateway."** (`boot.failure.remoteFailureHint`). **Remote-reauth set:** **"Sign out & sign in"** (`boot.failure.signOutAndSignIn`, `LogIn`, busy key `signin`), **"Gateway settings"** (`variant="secondary"`), **"Use local gateway"**; hint `boot.failure.remoteSignInHint(signInLabel)` = **"Signs out of the saved remote browser session, then opens {signInLabel}. Use local gateway to switch to the bundled backend instead."**. **Cloud-down set:** **"Check Portal status"** (`boot.failure.cloudDownCheckPortal`, `ExternalLink`), **"Use local gateway"**, **"Retry"** (`variant="secondary"`), **"Get help on Discord"** (`boot.failure.cloudDownDiscord`, `variant="ghost"`), **"Gateway settings"** (`variant="ghost"`); hint **"The buttons below open the Nous Portal (instance status and controls) and our Discord for support."** (`boot.failure.cloudDownHint`). **Log disclosure:** **"Show recent logs"** / **"Hide recent logs"** (see `gapfill-desktop-a-r0.boot-failure-recent-logs`). **Embedded settings view:** **"Back"** (see `gapfill-desktop-a-r0.boot-failure-connect-view`). Descriptions rendered under the headline: **"The background gateway didn't come up. Try one of the recovery steps below. Nothing here deletes your chats or settings."** (`boot.failure.description`), **"Your remote gateway session has expired. Sign in again to reconnect. Nothing here deletes your chats or settings."** (`boot.failure.remoteDescription`), **"The Nous-managed cloud agent this gateway connects to is returning a server error. It cannot be restarted from here — check its status, switch to the local gateway, or get support."** (`boot.failure.cloudDownDescription`). No keyboard shortcut, no Esc dismissal — the overlay is not dismissible.
- **Outputs / side effects:** `Retry` → `resetBootstrap()` then `window.location.reload()` (`:147-151`). `Repair install` → `repairBootstrap()` then reload (`:153-157`). `Use local gateway` → `applyConnectionConfig({ mode: 'local' })` (a soft re-home: tears down the primary and re-dials in place, shell stays) then clears the busy flag (`:159-164`). `Gateway settings` → in-place view swap, no navigation. `Open logs` → OS file manager reveals the log directory. `Check Portal status` → `openExternalLink('https://portal.nousresearch.com')`. `Get help on Discord` → `openExternalLink('https://discord.gg/NousResearch')`. While any action is busy **all** buttons are `disabled` and the busy one swaps its icon for a spinning `Loader2` (`:400-403`).
- **Config / env:** No config keys of its own. Reads the connection config written by the main process (`connection.json` / `connections.json`, see `desktop-main.connection-config-file` and `desktop-main.registry-file`) and the boot-progress payload fields `error`, `running`, `isCloudBackendDown`, `statusCode`, `retryable` (`apps/desktop/src/global.d.ts:1091-1110`).
- **Edge cases / guards:** Suppressed while first-run onboarding is mid-flow, but still covers it on a hard failure via a higher z-index (comment at `:64-67`). A `Repair` button is deliberately **dropped** from the remote and cloud-down sets because re-running the local installer cannot revive a dead remote (`:238-242`, `:298-303`). `Use local gateway` is deliberately dropped from the local set because it is redundant with Retry (`:326-327`). Portal/Discord are buttons, not URLs inside the hint prose, so a translated hint cannot drift the links (`:301-303`). A missing `window.hermesDesktop.getConnectionConfig` leaves the generic local variant; a failing `probeConnectionConfig` just keeps generic sign-in copy (`:123-131`). All IPC calls are `.catch(() => undefined)` so a rejected bridge call cannot wedge the recovery screen. Leaving the visible state resets `remoteReauth`, `connectionConfig`, `remoteFailure` and `view` (`:84-90`).
- **Rebuild notes:** Mount one always-present overlay keyed off `(bootError && !bootRunning)`; classify the failure into local / remote / remote-reauth / provider-outage from *structured* boot metadata, never message text; give each class its own ordered action list where the first button is the one that actually fixes that class; always append "open logs"; never make the fix-it links live inside translatable prose. A better version would show the failing step from the boot-progress phase, offer a one-click "copy diagnostics" of the last N log lines, and auto-retry transient classes with visible backoff before falling back to the manual buttons.

### Boot-failure overlay — embedded "Gateway settings" recovery view  `id: gapfill-desktop-a-r0.boot-failure-connect-view`
- **Surface:** Desktop app
- **Where:** Boot-failure overlay → **"Gateway settings"** button → the card body is replaced by the real Settings → Gateway panel, with a subtle **"Back"** affordance at the top-left (`i18n: boot.failure.back`, `apps/desktop/src/components/boot-failure-overlay.tsx:354-361`).
- **What it does:** Lets the user fix the connection (URL, auth mode, token, sign-in, test, save) without leaving the recovery screen and without a second, drift-prone connection form.
- **How it works:** `view` state is `'recovery' | 'connect'` (`:33`, `:61`). In `'connect'` the component returns a different card: `max-h-[86vh] w-full max-w-[46rem]`, a back button (`ChevronLeft` + `copy.back`) that sets `view` back to `'recovery'`, and `<GatewaySettings embedded />` inside a `<Suspense>` whose fallback is a centred `Loader` (`:343-369`). `GatewaySettings` is `lazy(() => import('@/app/settings/gateway-settings').then(m => ({ default: m.GatewaySettings })))` (`:28-30`) so the settings bundle stays out of the always-mounted overlay until opened.
- **Inputs / options:** **"Gateway settings"** (enters the view), **"Back"** (returns to the recovery view). Everything inside is the unmodified Settings → Gateway panel — same URL/auth/Test/Save controls (documented under `desktop-settings.*`).
- **Outputs / side effects:** Whatever the embedded panel does (saves `connection.json`, applies a connection, signs in). No navigation, no route change, no z-index juggling.
- **Config / env:** n/a
- **Edge cases / guards:** The `embedded` prop is what keeps the panel from painting its own page chrome. The overlay stays `data-glass-opaque=""` in this view too (`:349`), so window translucency never leaks the dead app behind the recovery card.
- **Rebuild notes:** Reuse the real settings component behind a lazy import rather than writing a recovery-only form; a second form is guaranteed to drift from the canonical one. A better version would deep-link straight to the field that failed (URL vs token vs auth mode).

### Boot-failure overlay — recent-logs disclosure  `id: gapfill-desktop-a-r0.boot-failure-recent-logs`
- **Surface:** Desktop app
- **Where:** Bottom of the boot-failure card, a small text button reading **"Show recent logs"** (`i18n: boot.failure.showRecentLogs`) when collapsed and **"Hide recent logs"** (`i18n: boot.failure.hideRecentLogs`) when expanded — `apps/desktop/src/components/boot-failure-overlay.tsx:422`.
- **What it does:** Reveals the tail of the backend's recent output inline, so the user (or a support thread) can see why the boot failed without hunting for the log file.
- **How it works:** `showLogs` state (`:52`) toggled by a `Button size="xs" variant="text"` (`:415-423`). Content is `logs.slice(-40).join('')` rendered inside `<LogView className="max-h-48">` (`:424`), i.e. the **last 40 lines** of what `window.hermesDesktop.getRecentLogs()` returned during the visibility effect (`:74-77`). `LogView` (`apps/desktop/src/components/ui/log-view.tsx:8`) is the shared raw-log viewer: hairline border, `font-mono text-[0.6875rem]`, `whitespace-pre-wrap break-words`, `overflow-auto`, `data-selectable-text="true"` so the text can be selected and copied.
- **Inputs / options:** One toggle button (two labels). The whole disclosure block is conditional on `logs.length > 0` (`:413`) — with no captured output there is no button at all.
- **Outputs / side effects:** Purely visual; no IPC on toggle. The log text is selectable/copyable.
- **Config / env:** n/a
- **Edge cases / guards:** A failing `getRecentLogs()` is swallowed (`.catch(() => undefined)`) and simply leaves the disclosure hidden. The 40-line cap and `max-h-48` scroll keep a runaway log from pushing the recovery buttons off-screen.
- **Rebuild notes:** Cap the tail at both a line count and a pixel height, keep it selectable, and hide the control entirely when there is nothing to show. A better version would also expose a "copy log tail" button wired to the same text the Send-diagnostics bundle attaches.

### Boot-failure overlay — remote reauth ("Sign out & sign in")  `id: gapfill-desktop-a-r0.boot-failure-reauth`
- **Surface:** Desktop app
- **Where:** The **"Remote gateway sign-in required"** variant of the boot-failure overlay; primary button **"Sign out & sign in"** (`i18n: boot.failure.signOutAndSignIn`, `LogIn` icon) — `apps/desktop/src/components/boot-failure-overlay.tsx:288`.
- **What it does:** Clears the stale saved browser session for this remote gateway and re-runs its owning login flow, then reloads the app so boot mints a fresh WebSocket ticket against the new session.
- **How it works:** Detection: `isRemoteReauthFailure(config, error)` (`boot-failure-reauth.ts:133`) = `isRemoteConfig(config) && config.remoteAuthMode === 'oauth' && (!config.remoteOauthConnected || isRemoteReauthError(error))`. `isRemoteConfig` (`:34`) is true for `mode === 'remote' | 'cloud'` with a `remoteUrl`, or `mode === 'ssh'` with an `sshHost`. `isRemoteReauthError` (`:52`) lower-cases the error and matches `remote gateway session has expired`, `gateway sign-in required`, `needs oauth login`, or `oauth` together with `not signed in` / `sign in` — because a stale refresh-token cookie can still make Settings read "connected", so the error text is part of the signal. `shouldApplyPostBootProgressError` (`:71`) gates post-boot progress errors on the same predicate so only a *confirmed* reauth escalates to the full-screen overlay (transient ticket-mint blips stay in the reconnect loop). Action: `signInRemote()` (`:170-227`) sets busy `signin`, calls `oauthLogoutConnectionConfig(url)`, then branches — for `connectionConfig.mode === 'cloud'` it checks `desktop.cloud.status()`, runs `desktop.cloud.login()` if not signed in, then `desktop.cloud.agentSignIn(url)`; otherwise `oauthLoginConnectionConfig(url)`. On `result.connected` a cloud connection additionally calls `resetBootstrap()`, then it toasts success and reloads.
- **Inputs / options:** **"Sign out & sign in"** (the action), plus the variant's other buttons **"Gateway settings"** and **"Use local gateway"**, and the hint `boot.failure.remoteSignInHint(label)` — **"Signs out of the saved remote browser session, then opens {signInLabel}. Use local gateway to switch to the bundled backend instead."**. The interpolated `signInLabel` comes from `signInLabel(remoteReauth, {identityProvider, remoteGateway, withProvider})` (`boot-failure-reauth.ts:156`, called at `boot-failure-overlay.tsx:232-236`): a password-style gateway yields **"Sign in to remote gateway"** (`i18n: boot.failure.signInToRemoteGateway`), anything else yields **"Sign in with {provider}"** (`i18n: boot.failure.signInWithProvider`) with the probed provider label or the fallback **"your identity provider"**.
- **Outputs / side effects:** Clears the per-connection OAuth cookie partition, opens the login window (embedded OAuth window or RFC 8252 system-browser flow, see `desktop-main.oauth-login-window` / `desktop-main.native-oauth`), and on success toasts + `window.location.reload()`. On a cloud connection it also resets the bootstrap latch. Failure paths toast (see `gapfill-desktop-a-r0.signin-outcome-toasts`). `busy` is always cleared in the `finally` block (`:224-226`).
- **Config / env:** `connection.json` fields `mode`, `remoteUrl`, `remoteAuthMode`, `remoteOauthConnected`; bridge methods `oauthLogoutConnectionConfig`, `oauthLoginConnectionConfig`, `cloud.status`, `cloud.login`, `cloud.agentSignIn`, `probeConnectionConfig`, `resetBootstrap`.
- **Edge cases / guards:** `signInRemote()` returns immediately if `remoteReauth` is null. An early-return after a failed `cloud.login()` leaves the overlay open with the warning toast. `Retry` / `Repair install` are explicitly *not* offered as the lead here because they only target the bundled local backend (comment at `:35-40`). The reauth helpers live in a plain `.ts` module precisely so they can be unit-tested without a React render (comment at `boot-failure-reauth.ts:4-7`).
- **Rebuild notes:** Treat "credentials expired" as a distinct failure class from "transport unhealthy"; always sign *out* before signing back in so a half-valid cookie cannot short-circuit the flow; reload after success so the socket ticket is minted against the new session. A better version would refresh the token silently in the background and only surface the overlay when the silent refresh is refused.

### Remote sign-in outcome toasts (shared by three surfaces)  `id: gapfill-desktop-a-r0.signin-outcome-toasts`
- **Surface:** Desktop app
- **Where:** Raised as toasts after any remote-gateway OAuth sign-in attempt, from three call sites: the boot-failure overlay (`apps/desktop/src/components/boot-failure-overlay.tsx:191-221`), Settings → Gateway (`apps/desktop/src/app/settings/gateway-settings.tsx:620-630` for the panel's own Sign in and `:896-903` for a Hermes Cloud agent sign-in), and the Connections registry editor (`apps/desktop/src/app/settings/connections-registry.tsx:341-353`).
- **What it does:** Tells the user whether the login window actually completed authentication, and what happens next.
- **How it works:** Three outcomes, all through `notify` / `notifyError` from `@/store/notifications`. **Success:** `notify({ kind: 'success', title: t.boot.failure.signedInTitle, message: t.boot.failure.signedInMessage })` → **"Signed in"** / **"Reconnecting to the remote gateway…"** (`i18n: boot.failure.signedInTitle` / `boot.failure.signedInMessage`, `boot-failure-overlay.tsx:211`), followed by `window.location.reload()`. **Incomplete:** `notify({ kind: 'warning', title: t.boot.failure.signInIncompleteTitle, message: t.boot.failure.signInIncompleteMessage })` → **"Sign-in incomplete"** / **"The login window closed before authentication finished."** (`i18n: boot.failure.signInIncompleteTitle` / `boot.failure.signInIncompleteMessage`) — raised both when `cloud.login()` returns `signedIn: false` (`:191-195`) and when the connection login returns `connected: false` (`:217-221`); the identical pair is reused verbatim by Gateway settings (`gateway-settings.tsx:624-625`, `:899-900`) and by the Connections registry (`connections-registry.tsx:350-351`) so the three surfaces cannot drift. **Failure (throw):** `notifyError(err, t.boot.failure.signInFailed)` → title **"Sign-in failed"** (`i18n: boot.failure.signInFailed`, `:223`); Gateway settings and the registry use their own `t.settings.gateway.signInFailed` fallback for the same shape. Settings' success path instead toasts `g.signedIn` with `g.connectedTo(providerLabel)`.
- **Inputs / options:** None — these are output-only. Placement follows the store default: `warning` and `error` toasts go to the top-centre stack, the `success` toast has no action and no `warning`/`error` kind so it lands in the quiet bottom-right stack (`apps/desktop/src/store/notifications.ts:67-73`).
- **Outputs / side effects:** A toast in the appropriate stack; on success also a full renderer reload (overlay path) or an `acceptSavedConfig` + soft reconnect (settings path).
- **Config / env:** n/a
- **Edge cases / guards:** Sequence guards (`seq !== signingSeq.current`, `seq !== contextSeq.current`, generation counters) drop stale results so a slow login window cannot toast over a newer attempt (`gateway-settings.tsx:610-614`, `:892-894`). Warning-kind toasts have `durationMs = 0` (`notifications.ts:52-58`), i.e. they persist until dismissed — a user who missed the login window still sees why nothing happened.
- **Rebuild notes:** Model the three outcomes explicitly (completed / window closed early / threw); share one string pair across every surface that can start the same login; never treat a closed window as an error. A better version would re-open the login window from the toast itself with a "Try again" action.

### Remote auth provider label fallback ("your identity provider")  `id: gapfill-desktop-a-r0.identity-provider-fallback`
- **Surface:** Desktop app
- **Where:** Interpolated into sign-in button copy and hints wherever the desktop must name the remote gateway's identity provider but the probe returned none: the boot-failure overlay (`boot-failure-overlay.tsx:233`), Settings → Gateway's provider label (`gateway-settings.tsx:394`) and the Connections registry editor (`connections-registry.tsx:277`). Verbatim string: **"your identity provider"** (`i18n: boot.failure.identityProvider`).
- **What it does:** Gives the sign-in copy a sensible name when the gateway advertises no providers, so the button reads "Sign in with your identity provider" instead of "Sign in with undefined".
- **How it works:** `deriveRemoteAuthProviderShape(providers, fallback = 'your identity provider')` (`apps/desktop/src/lib/desktop-remote-auth.ts:12-26`) returns `{ isPassword: false, providerLabel: fallback }` for an empty/absent provider list; otherwise `isPassword = list.every(p => Boolean(p.supportsPassword))` (a *mixed* deployment therefore keeps the generic OAuth copy) and `providerLabel = list.map(p => p.displayName || p.name).join(' / ')`. `deriveProviderShape` in `boot-failure-reauth.ts:148` is a thin re-export used by the overlay. Gateway settings computes the same label inline (`gateway-settings.tsx:388-395`): one provider → its `displayName || name`, several → joined with `' / '`, none → `t.boot.failure.identityProvider`. `signInLabel()` (`boot-failure-reauth.ts:156-165`) then maps the shape onto the button text, substituting the caller's `identityProvider` copy when the label is still the default sentinel.
- **Inputs / options:** `providers: DesktopAuthProvider[]` from `probeConnectionConfig(url)`; each entry has `name`, `displayName`, `supportsPassword`.
- **Outputs / side effects:** Only text: **"Sign in with your identity provider"**, or **"Sign in to remote gateway"** for an all-password gateway, or **"Sign in with {displayName}"** / **"Sign in with {A / B}"**.
- **Config / env:** n/a
- **Edge cases / guards:** The probe is best-effort and debounced in the registry editor so typing a URL does not fire one request per keystroke (`connections-registry.tsx:279-289`); a failed probe never blocks signing in, it just leaves the generic label. The default fallback is duplicated as a literal in `DEFAULT_SIGN_IN_COPY` (`boot-failure-reauth.ts:24-28`) and in `deriveRemoteAuthProviderShape`'s default parameter, and the sentinel comparison at `:162` is what lets a localized caller override it.
- **Rebuild notes:** Always give provider-name interpolation a translatable fallback and compare against the sentinel rather than against `undefined`. A better version would cache the probe per URL and show the provider's icon next to its name.

### Toast / notification stack  `id: gapfill-desktop-a-r0.notification-stack`
- **Surface:** Desktop app
- **Where:** Two portaled regions on `document.body`, both labelled **"Notifications"** (`i18n: notifications.region`, `role="region"`): a **top-centre** stack under the titlebar (`top-[calc(var(--titlebar-height,34px)+0.75rem)]`, `w-[min(40rem,calc(100%-2rem))]`) and a **bottom-right** ambient stack (`right-4 bottom-4`, `w-[min(24rem,calc(100%-2rem))]`, newest on top via `flex-col-reverse`). Mounted once as `<NotificationStack />` in `apps/desktop/src/app/contrib/wiring.tsx:1242` ("Toasts above everything."). Component: `apps/desktop/src/components/notifications.tsx:47`.
- **What it does:** Shows transient app messages — errors, warnings, confirmations, action prompts — as toasts, with an expander when several queue up and a per-toast close button.
- **How it works:** `$notifications` is a nanostore atom of `AppNotification[]` (`apps/desktop/src/store/notifications.ts:50`). `partitionNotifications` (`notifications.tsx:32`) splits on `placement`: `'bottom-right'` → ambient stack, everything else → `TopCenterStack`. `defaultPlacement(kind, action)` (`store/notifications.ts:67-73`) sends `error`, `warning` and *anything with an action button* to the top-centre stack and everything else (the bulk of "saved" / "enabled" / "archived" confirmations) to the quiet bottom-right one. `defaultDuration` (`:52-58`) is `0` (sticky) for `error`/`warning` and `5_000` ms otherwise; `notify()` (`:157-190`) clears any existing timer for the id, prepends the notification and **caps the list at 4** (`.slice(0, 4)`), then arms a dismissal timer when duration > 0. `dismissNotification(id)` (`:203-209`) clears the timer, removes the item and fires its `onDismiss`; `clearNotifications()` (`:211-223`) clears every timer and fires every `onDismiss`. Both stacks are `createPortal(...)`-ed to `<body>` on the `z-(--z-over-modal)` rung so a toast fired while a dialog is open is not painted over (comment at `:95-103`). A `useEffect` on the newest notification triggers haptics: `triggerHaptic('success' | 'error' | 'warning')` by kind (`:62-78`). Each item renders as an `Alert` with `aria-live="assertive"` + `role="alert"` for errors and `aria-live="polite"` + `role="status"` otherwise (`:212-214`); the tone table (`:23-28`) maps `error → AlertCircle / text-destructive / destructive`, `warning → AlertTriangle / text-primary / warning`, `info → Info / text-muted-foreground / default`, `success → CheckCircle2 / text-primary / success`. `renderMessage` (`:169-188`) bolds and accent-tints the first `$N`/`$N.NN` figure in the message when `accentColor` is set (the credits/usage ramp). `toastTitleClassName()` (`:193`) lets a long title wrap up to `max-h-[4.5em]` and scroll instead of clipping.

### Error-summarizer table (friendly toast summaries)  `id: gapfill-desktop-a-r0.error-summaries`
- **Surface:** Desktop app
- **Where:** Invisible plumbing behind every `notifyError(...)` toast; the strings it emits are what the user reads as the toast message. `ERROR_SUMMARIES` in `apps/desktop/src/store/notifications.ts:91-133`.
- **What it does:** Rewrites long, raw provider/gateway/OS error dumps into a single actionable sentence that names the missing key or the real fix, instead of showing an errno blob or truncating mid-JSON.
- **How it works:** `notifyError(error, fallback)` (`:192-201`) calls `readableError(error, fallback)` → `summarizeErrorMessage(detail, fallback)` (`:135-143`), which finds the **first** matching rule in the ordered `ERROR_SUMMARIES` array and returns `rule.summarize(msg)`; with no match it returns the message unchanged unless it exceeds **180 characters**, in which case the caller's `fallback` title text is used as the message. Every summary resolves through `translateNow('<key>')` (`apps/desktop/src/i18n/runtime.ts:64`), so the table is locale-aware. The seven rules, in order: **(1)** `isDiskFullErrorMessage(msg)` → **"Disk full — free some space, then try again."** (`i18n: notifications.errors.diskFull`) — deliberately first, before generic truncation, so a full disk never reads as a silent send (comment at `:93-96`); **(2)** `/['"]code['"]\s*:\s*['"]gateway_auth_failed['"]/i` → **"Gateway authentication failed — check your API_SERVER_KEY."** (`i18n: notifications.errors.gatewayAuthFailed`); **(3)** `/incorrect api key provided/i` or `"code":"invalid_api_key"` → if the message carries a 3-digit status (`/(?:error code|status(?:Code)?)[^\d]*(\d{3})/i`) then **"OpenAI rejected the API key ({status} invalid_api_key)."** (`i18n: notifications.errors.openaiRejectedApiKeyWithStatus`), else **"OpenAI rejected the API key."** (`i18n: notifications.errors.openaiRejectedApiKey`); **(4)** `/neither voice_tools_openai_key nor openai_api_key is set/i` → **"OpenAI TTS needs VOICE_TOOLS_OPENAI_KEY or OPENAI_API_KEY."** (`i18n: notifications.errors.openaiTtsNeedsKey`); **(5)** `/ELEVENLABS_API_KEY not set/i` or `/ElevenLabs STT API error \(HTTP 401\)/i` → **"ElevenLabs STT needs ELEVENLABS_API_KEY."** (`i18n: notifications.errors.elevenLabsNeedsKey`) for the missing-key branch and **"ElevenLabs rejected the API key (401)."** (`i18n: notifications.errors.elevenLabsRejectedKey`) for the 401 branch; **(6)** `/method not allowed/i` → **"The desktop backend rejected that request (405 Method Not Allowed). Try restarting Hermes Desktop."** (`i18n: notifications.errors.methodNotAllowed`); **(7)** `/microphone permission/i` → **"Microphone permission was denied."** (`i18n: notifications.errors.microphonePermission`).
- **Inputs / options:** `notifyError(error: unknown, fallback: string)` — `error` may be an `Error`, a string, or anything else (then `fallback` is used); `fallback` doubles as the toast **title**. `readableError` is exported so inline surfaces (e.g. `ConfirmDialog`'s `onConfirm` rethrow) reuse the identical unwrapping + summarising (comment at `:145-146`). `isDiskFullErrorMessage` is exported for the stream paths below.
- **Outputs / side effects:** A `kind: 'error'` toast in the top-centre stack whose title is `fallback`, message is the summary, and `detail` is the raw text when it differs. Errors are sticky (`durationMs = 0`).
- **Config / env:** Names the environment variables the user must set: `API_SERVER_KEY`, `ELEVENLABS_API_KEY`, `VOICE_TOOLS_OPENAI_KEY`, `OPENAI_API_KEY`.
- **Edge cases / guards:** Rule order matters — disk-full is matched before everything else, and the ElevenLabs rule must re-test the message inside `summarize` to pick the missing-key vs 401 wording. The 180-character cut-off only applies when no rule matched. `cleanErrorText` strips a leading `Error: ` before matching (`:75-77`), and the IPC unwrap regex (`:149`) removes Electron's `Error invoking remote method '…'` prefix so patterns match the real payload.
- **Rebuild notes:** Keep an ordered `[{test, summarize}]` table, resolve every summary through the i18n runtime (not a literal), preserve the raw text as `detail`, and cap unmatched messages rather than letting a JSON dump fill the toast. A better version would key on structured error codes from the backend instead of regexes over English prose, and attach a one-click fix (open the settings field that holds the missing key).

### Disk-full detection and toast (ENOSPC / SQLITE_FULL)  `id: gapfill-desktop-a-r0.disk-full`
- **Surface:** Desktop app

A better version would report free bytes and offer to open the session-DB directory or run a cleanup.

Escape inside the name field is `preventDefault`/`stopPropagation`'d so it cannot bubble to the escape layer.
- **Rebuild notes:** Keep the geometric model (integer model units, guillotine-cut detection) separate from the React canvas, drive Save's enablement from a *probe run of the real converter* rather than a heuristic, and assign panes to zones by semantic role rather than index order. It then calls the optional `onError` prop. **Targeted auto-recovery:** when `label === 'root'` and the message matches `/(useClientLookup|tapClient(Lookup|Resource)).*out of bounds/` — a known transient assistant-ui lookup race — it retries by clearing the error on a `setTimeout(0)`, capped at `MAX_AUTO_RECOVERIES = 3` within an `AUTO_RECOVERY_WINDOW_MS = 5000` sliding window, so a persistent failure still reaches the fallback (`:24-29`, `:78-82`, `:196-207`). `componentDidMount` re-schedules a recovery that React StrictMode's synthetic unmount cancelled (`:41-49`). Render: children when no error; the `fallback({error, reset})` prop when supplied; otherwise `<RootErrorFallback>`. The fallback is an `ErrorState` card capped at `max-w-[28rem]`, centred on `--ui-chat-surface-background`, with `data-glass-opaque=""` so a crashed app is never see-through under window glass. The description prefers `error.message` and falls back to `errors.boundaryDesc`.
- **Inputs / options:** Props: `children`, `fallback?`, `label?`, `onError?`. Buttons in the default fallback (3): **"Retry"** (`i18n: common.retry`, `size="lg"`, semibold, calls `reset()` which clears the timer, the pending flag, the recovery counter and the window start, then clears the error), **"Reload window"** (`i18n: errors.reloadWindow`, text variant, `window.location.reload()`), and **"Open logs"** (`i18n: errors.openLogs`, text variant, `window.hermesDesktop?.revealLogs()?.catch(() => undefined)`). No keyboard shortcut; the screen is not dismissible any other way.
- **Outputs / side effects:** A `[error-boundary:*]` console entry, an IPC renderer-error report persisted to `desktop.log` (formatted main-side by `formatRendererBoundaryReport` in `electron/renderer-log.ts`, see `desktop-main.md:259`), and — on **"Open logs"** — the OS file manager revealing the log directory.
- **Config / env:** n/a
- **Edge cases / guards:** Auto-recovery is deliberately narrow: only the root boundary, only that one regex, at most three attempts per 5 s window — arbitrary render failures are never retried. The report call is defensive because `window.hermesDesktop` is absent in a plain browser. StrictMode's double-mount is explicitly handled so a development remount does not swallow the pending recovery. `reset()` restores the full counter state, so a user-driven retry is not charged against the auto-recovery budget.
- **Rebuild notes:** Log the component stack through a durable channel, not `console.error`; auto-retry only an allow-listed transient error class with a hard attempt cap; keep the fallback reassuring about data safety and give exactly three actions (retry / reload / logs). A better version would attach the last N renderer log lines to the crash card and offer a one-click diagnostics upload (the `Send diagnostics` flow already documented above).

The clear button is `Button size="icon-xs" variant="ghost"` wrapping a `close` codicon at `0.875rem`, wrapped in a `Tip`. Placeholder hints: when `hints` is a non-empty array, one is chosen **once per mount** by `Math.floor(Math.random() * 4096) % hints.length` (`:53-55`) — a fresh nudge per visit, never a mid-page carousel — otherwise the plain `placeholder` is used. The container is `inline-flex min-w-0 max-w-full … border-b border-transparent`, sits at `opacity-30` until it has a value or focus-within (`:63-66`); the input is `h-7 … text-xs [field-sizing:content]` so it grows to fit its content and shrinks below it in a narrow context, with `aria-label` defaulting to the placeholder.
- **Inputs / options:** Props — `placeholder` (required), `value` (required), `onChange` (required), `hints?`, `containerClassName?`, `inputClassName?`, `loading?` (default `false`), `onClear?`, `inputRef?`, `trailingAction?`, `aria-label`. - **Outputs / side effects:** Clicking clear calls `onClear` or emits `onChange('')`; nothing is persisted by the primitive itself.
- **Config / env:** n/a
