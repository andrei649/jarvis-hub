Scope: two leftovers from the desktop-b surface that the mechanical i18n checker flagged as
uncovered. (1) The weekday-name lookup `dayName()` behind the cron editor's human schedule

### Cron schedule summary — weekday names (“Every Wednesday at 9:00 AM”)  `id: gapfill-desktop-b-r2.cron-day-names`
- **Surface:** Desktop app
- **Where:** Scheduled jobs panel (`/cron`) → cron editor dialog (**“New cron job”** / **“Edit cron job”**) → **“Frequency”** select set to **“Weekly”** (`i18n: cron.scheduleLabels.weekly`) → the read-only summary strip under the select, left-hand sentence. Template **“Every {day} at {time}”** (`i18n: cron.everyDayOfWeekAt`), e.g. the rendered strings **“Every Sunday at 9:00 AM”**, **“Every Monday at 9:00 AM”**, **“Every Tuesday at 9:00 AM”**, **“Every Wednesday at 9:00 AM”**, **“Every Thursday at 9:00 AM”**, **“Every Friday at 9:00 AM”**, **“Every Saturday at 9:00 AM”**. The same `scheduleSummary()` output is also what the strip's right half pairs with the raw cron expression in mono.
- **What it does:** Converts the 5th cron field (day-of-week) of a weekly job into a human weekday noun, so the editor can show “Every Wednesday at 9:00 AM” instead of `0 9 * * 3`.
- **How it works:** `dayName(value, c)` at `apps/desktop/src/app/cron/index.tsx:157-159` is a one-liner: `return c.days[value] ?? c.dayFallback(value)`. It is called from exactly one place — `scheduleSummary()` at `apps/desktop/src/app/cron/index.tsx:252`, inside the `option.value === 'weekly'` branch: `c.everyDayOfWeekAt(dayName(dayOfWeek, c), formatCronTime(minute, hour))`. `dayOfWeek` is the raw **string** token at index 4 of `cronParts(expr)` (`cron/index.tsx:151-155`: trim → collapse runs of whitespace → split on `' '`, returning `null` unless exactly 5 fields), so the lookup key is a string, not a number. The `weekly` preset is only chosen by `scheduleOptionForExpr()` when `dayOfMonth === '*' && month === '*' && isIntegerToken(dayOfWeek) && isIntegerToken(minute) && isIntegerToken(hour)` (`cron/index.tsx:203-212`, `isIntegerToken` = `/^\d+$/`, `cron/index.tsx:176-178`), or by exact match on the preset expression `0 9 * * 1` (`SCHEDULE_OPTIONS`, `cron/index.tsx:101-109`). The time half is `formatCronTime(minute, hour)` (`cron/index.tsx:161-173`), which builds `new Date(2000, 0, 1, hour, minute)` and formats it with `toLocaleTimeString(undefined, { hour: 'numeric', minute: '2-digit' })` — hence “9:00 AM” under an en-US locale — falling back to the literal `${hour}:${minute}` when either field is not an integer. The catalog map is a plain object, `days` in the `cron` namespace, `apps/desktop/src/i18n/en.ts:2024-2033`, typed `days: Record<string, string>` with a sibling `dayFallback: (value: string) => string` at `apps/desktop/src/i18n/types.ts:1707-1708`. No state, no storage — pure formatting recomputed on every render of the editor.
- **Inputs / options:** The eight catalog entries, verbatim and complete — **“Sunday”** (`i18n: cron.days.0`, `en.ts:2025`), **“Monday”** (`i18n: cron.days.1`, `en.ts:2026`), **“Tuesday”** (`i18n: cron.days.2`, `en.ts:2027`), **“Wednesday”** (`i18n: cron.days.3`, `en.ts:2028`), **“Thursday”** (`i18n: cron.days.4`, `en.ts:2029`), **“Friday”** (`i18n: cron.days.5`, `en.ts:2030`), **“Saturday”** (`i18n: cron.days.6`, `en.ts:2031`), **“Sunday”** (`i18n: cron.days.7`, `en.ts:2032` — the second Sunday, see guards). Plus the miss path **“day {value}”** (`i18n: cron.dayFallback`, `en.ts:2034`, e.g. the rendered **“day 9”**). The wrapper templates that consume them: **“Every {day} at {time}”** (`cron.everyDayOfWeekAt`, `en.ts:2037`) and, for the neighbouring presets, **“Every day at {time}”** (`cron.everyDayAt`), **“Weekdays at {time}”** (`cron.weekdaysAt`), **“Monthly on day {dayOfMonth} at {time}”** (`cron.monthlyOnDayAt`), **“At the top of every hour”** (`cron.topOfHour`), **“Every hour at :{minute}”** (`cron.everyHourAt`). There is no user-facing control here: the only “input” is the day-of-week field the user types into **“Custom schedule”** (`cron.customPlaceholder` **“0 9 * * * or weekdays at 9am”**) or that the chosen preset supplies.
- **Outputs / side effects:** A display string only. Nothing is written to disk or sent to the backend — the persisted value stays the raw cron expression (`schedule`), and the same expression is echoed verbatim in mono next to the sentence.
- **Config / env:** Language selection only (desktop i18n locale). Localised maps exist per catalog, e.g. `apps/desktop/src/i18n/ar.ts:1554-1562` (**“الأحد”**, **“الاثنين”**, **“الثلاثاء”**, **“الأربعاء”**, **“الخميس”**, **“الجمعة”**, **“السبت”**, **“الأحد”**) with `dayFallback` `اليوم ${value}` (`ar.ts:1563`), plus `ja.ts:1708`, `zh.ts:2205`, `zh-hant.ts:1646`. The clock format follows the host's `Intl` locale (`toLocaleTimeString(undefined, …)`), so a 24-hour locale shows “09:00”, not “9:00 AM”.
- **Edge cases / guards:** (1) **DOW 7 is a deliberate alias of 0** — cron accepts both `0` and `7` for Sunday, so the map holds eight entries with a duplicated label; `0 9 * * 7` renders the identical sentence as `0 9 * * 0`. (2) Any integer token outside 0–7 (`0 9 * * 9`) still passes `isIntegerToken`, misses the map and falls through to `cron.dayFallback` → **“day 9”**; the same happens for a zero-padded token such as `08`, because the lookup is by string (`days['08']` is undefined) → **“day 08”**. (3) Ranges and lists never reach `dayName`: `1-5` is caught earlier as the `weekdays` preset, and `1,3` / `MON` fail `isIntegerToken`, so `scheduleOptionForExpr()` falls through to the last option `custom` and the strip shows the static hint **“Cron syntax or natural language”** (`cron.scheduleHints.custom`) instead. (4) If the expression is not exactly 5 whitespace-separated fields, `cronParts()` returns `null` and `scheduleSummary()` short-circuits to `c.scheduleHints[option.value]` before `dayName` is ever called (`cron/index.tsx:230-234`). (5) Named-day cron syntax (`SUN`, `MON`) is not supported by this formatter at all — it is passed to the backend untouched but only ever summarised as “Custom”.
- **Rebuild notes:** Minimum: a `Record<string,string>` keyed by the raw DOW token with both `'0'` and `'7'` mapped to Sunday, a `dayFallback(value) => \`day ${value}\`` escape hatch, and a `weekly` branch that formats `everyDayOfWeekAt(dayName(dow), formatTime(min, hour))`. A better version would parse the whole DOW field (ranges, lists, `MON-FRI`, `SUN` aliases, and the `L`/`#` extensions) into a normalised set and render “Every Tuesday and Thursday at 9:00 AM” with an `Intl.ListFormat`-joined list plus `Intl.DateTimeFormat({weekday:'long'})` names, so the map needs no per-locale translation and the summary never degrades to “Custom”.
