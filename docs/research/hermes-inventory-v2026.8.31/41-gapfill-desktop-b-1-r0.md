# Gap-fill — Desktop app: session/prompt action feedback, image + export flows, shared UI primitives (round 0, area desktop-b-1)

This shard closes gaps the string checker found in the Hermes Desktop (Electron/React) renderer: the toast/notification vocabulary emitted by the session and prompt action hooks (`apps/desktop/src/app/session/hooks/**`), the composer image-attach and image-save flows, session export, the tab-close confirmation, the stranded-session recovery state, and the two shared shadcn-style primitives (Pagination, Sidebar sheet) whose accessible labels no other shard captured.
It documents each feature end-to-end (mechanism, RPC, storage, every visible string) so the labels are anchored to real behaviour rather than listed as orphan strings.
It deliberately leaves to sibling shards: the surfaces that merely *host* these actions (composer, sidebar rows, transcript, Artifacts page — `desktop-b.md`), the Electron main-process IPC handlers behind `window.hermesDesktop.*` (`desktop-main.md`), Settings fields (`desktop-settings.md`), and the gateway-side implementations of `session.*` / `handoff.*` / `config.set` RPCs (`tui.md`, `gw-core.md`).
Labels that already had a home were appended in place to `desktop-b.md` (session date dividers, preview DevTools toggle, checkpoint "next" control, Artifacts pagination aria, `/skin` theme completions) rather than duplicated here.

### Shared Pagination primitive (Prev / page numbers / Next)  `id: gapfill-desktop-b-1-r0.shared-pagination`
- **Surface:** Desktop app
- **Where:** `apps/desktop/src/components/ui/pagination.tsx`. Rendered today by the Artifacts table footer (`apps/desktop/src/app/artifacts/index.tsx:416` `ArtifactsPagination`, imports at `:11-18`), bottom-right of the Artifacts page under the image grid and under the table.
- **What it does:** A reusable, i18n-labelled pager: a Prev button, numbered page buttons with an ellipsis gap, and a Next button, wrapped in a landmark `nav`.
- **How it works:** Six exported components, all plain buttons (no anchors, so nothing can navigate the Electron window away): `Pagination` renders `nav[aria-label=t.ui.pagination.label][data-slot="pagination"]` (`pagination.tsx:7-18`); `PaginationContent` is `ul[data-slot="pagination-content"]` with `gap-0.5` (`:20-24`); `PaginationItem` is `li[data-slot="pagination-item"]` (`:26-28`); `PaginationButton` is the numbered page button — `aria-current="page"` when `isActive`, `data-active={isActive}`, `data-slot="pagination-button"`, `type="button"`, `h-5 min-w-5` tabular-nums (`:33-49`); `PaginationPrevious` (`:53-71`) and `PaginationNext` (`:73-91`) render a chevron plus the visible short label; `PaginationEllipsis` (`:93-103`) is an `aria-hidden` span with the `ellipsis` codicon. All labels come from `useI18n()` at render time, so a language switch repaints them without remount. The caller owns page state: `ArtifactsPagination` computes `pageCount = Math.max(1, Math.ceil(total / pageSize))`, hides the whole pager when `pageCount` is 1 or less, and builds the number row with `paginationItems(page, pageCount)` (`artifacts/index.tsx:68`) which prints every page when `pageCount` is 7 or less and otherwise `1 … page-1, page, page+1 … last`.
- **Inputs / options:** **“Prev”** (`i18n: ui.pagination.previous`) with `aria-label` **“Go to previous page”** (`i18n: ui.pagination.previousAria`) and a `chevron-left` codicon at `0.75rem`; `disabled` when `page <= 1`; click → `onPageChange(Math.max(1, page - 1))`. **“Next”** (`i18n: ui.pagination.next`) with `aria-label` **“Go to next page”** (`i18n: ui.pagination.nextAria`) and a `chevron-right` codicon; `disabled` when `page >= pageCount`; click → `onPageChange(Math.min(pageCount, page + 1))`. Numbered buttons: label = the page number, `aria-label` supplied by the caller (Artifacts passes **“Go to {itemLabel} page {n}”**, `artifacts.goToPage`), click → `onPageChange(n)`. Ellipsis: not focusable, no action. The wrapping nav's `aria-label` is **“pagination”** (`i18n: ui.pagination.label`). No keyboard shortcut of its own — they are ordinary tab-stops.
- **Outputs / side effects:** Pure UI; the only effect is the caller's `onPageChange` callback (Artifacts re-slices its in-memory artifact list — no network call).
- **Config / env:** n/a
- **Edge cases / guards:** Disabled buttons use `disabled:pointer-events-none disabled:opacity-45` so a disabled Prev/Next cannot be clicked or hovered; `PaginationEllipsis` is `aria-hidden` so screen readers hear only real pages; the four labels live under `ui.pagination.*` (`apps/desktop/src/i18n/en.ts:3537-3543`) and are translated per locale.
- **Rebuild notes:** Minimum: `nav > ul > li` with buttons, distinct visible label vs `aria-label` for Prev/Next, `aria-current="page"` on the active number, ellipsis `aria-hidden`, and a 7-or-fewer / windowed algorithm. A better version would add `rel="prev"/"next"` semantics, an "N of M" live region announced on change, and page-size selection.

### Shared Sidebar primitive — mobile/narrow sheet  `id: gapfill-desktop-b-1-r0.ui-sidebar-sheet`
- **Surface:** Desktop app
- **Where:** `apps/desktop/src/components/ui/sidebar.tsx:131-182`. Wraps the chat session sidebar (`apps/desktop/src/app/chat/sidebar/index.tsx` — sessions + cron sections) and the contributed controller sidebar; only visible when the window is narrow enough that `useIsMobile()` reports mobile.
- **What it does:** Below the mobile breakpoint the sidebar stops being a docked column and becomes an overlay sheet that slides in from the chosen side; the sheet carries a screen-reader-only header so assistive tech can name and describe it.
- **How it works:** `Sidebar({side='left', variant='sidebar', collapsible='offcanvas'})` reads `useSidebar()` for `isMobile`, `state`, `openMobile`, `setOpenMobile`. Three render paths: (1) `collapsible === 'none'` → a plain `div.h-full.w-(--sidebar-width)` column, no sheet; (2) `isMobile` → `Sheet` + `SheetContent[data-mobile="true"][data-sidebar="sidebar"][data-slot="sidebar"]` with `--sidebar-width: SIDEBAR_WIDTH_MOBILE` and the sheet's own close button hidden (`[&>button]:hidden`), containing a `SheetHeader.sr-only` with `SheetTitle` = `t.ui.sidebar.title` and `SheetDescription` = `t.ui.sidebar.description`, then the children in a full-height flex column; (3) desktop → the `hidden md:block` peer group with `data-collapsible`, `data-side`, `data-state`, `data-variant` attributes driving the CSS gap/rail behaviour.
- **Inputs / options:** Props: `side` (`'left' | 'right'`, default `'left'`), `variant` (`'sidebar' | 'floating' | 'inset'`, default `'sidebar'`), `collapsible` (`'offcanvas' | 'icon' | 'none'`, default `'offcanvas'`), plus `className` and any `div` props. Open/close is driven by `openMobile` / `setOpenMobile` from the sidebar context (the titlebar sidebar toggle and the `SidebarTrigger`), and the sheet closes on overlay click or Escape like any Radix dialog.
- **Outputs / side effects:** Screen readers announce the sheet as **“Sidebar”** (`i18n: ui.sidebar.title`) with the description **“Displays the mobile sidebar.”** (`i18n: ui.sidebar.description`). The toggle control elsewhere reads **“Show sidebar”** / **“Hide sidebar”** (`i18n: ui.sidebar.toggle`, a function of the open state). Nothing is persisted by this component.
- **Config / env:** n/a — width comes from the CSS custom properties `--sidebar-width` / `--sidebar-width-icon` / `SIDEBAR_WIDTH_MOBILE`.
- **Edge cases / guards:** The title and description are `sr-only`, so sighted users never see them — but Radix warns (and axe fails) on a dialog with no accessible description, which is exactly what this header exists to satisfy. `collapsible='none'` bypasses the sheet entirely, so a sidebar rendered that way has no dialog semantics at all.
- **Rebuild notes:** Minimum: below the breakpoint render the sidebar inside a dialog/sheet with an `sr-only` title+description pair and hide the built-in close button; keep the data attributes so CSS, not JS, animates the collapse. A better version would trap focus back onto the trigger on close and announce the collapsed/expanded state change in a live region.

### "Close running tab?" confirmation  `id: gapfill-desktop-b-1-r0.tile-close-confirm`
- **Surface:** Desktop app
- **Where:** Fires from the tab strip / session tile close affordance (the tab's ✕, the tab context menu close verbs). The dialog component `SessionTileCloseConfirm` is mounted once at the shell root; source `apps/desktop/src/app/chat/session-tile.tsx:489-509`.
- **What it does:** Closing a chat tab whose session is still working, awaiting a response, or blocked on your input asks first, and explains that closing only hides the tab — the session keeps running and can be reopened.
- **How it works:** `requestCloseSessionTile(storedSessionId)` (`session-tile.tsx:478-487`) resolves the tile's `runtimeId` from `$sessionTiles`, reads that runtime's slice out of `$sessionStates`, and if `state.busy || state.awaitingResponse || state.needsInput` it sets the module atom `$confirmCloseTile` to the stored id; otherwise it calls `closeSessionTile(storedSessionId)` immediately. `SessionTileCloseConfirm` subscribes to that atom and renders a `ConfirmDialog` with `destructive` styling, `open={storedSessionId !== null}`; confirming calls `closeSessionTile(storedSessionId)`, closing (Escape / overlay / cancel) sets the atom back to `null`. State is one nanostores atom (`null` = no dialog) — nothing is written to disk.
- **Inputs / options:** Title **“Close running tab?”** (`i18n: zones.closeRunningTitle`). Body **“This chat is still working (or waiting on your input). Closing the tab hides it — the session keeps its progress and can be reopened from the sidebar.”** (`i18n: zones.closeRunningBody`). Confirm button **“Close tab”** (`i18n: zones.closeRunningConfirm`, destructive variant). Cancel is the shared `ConfirmDialog` cancel. Related tab-strip verbs that can route here: **“Reload”** (`zones.reload`), **“Close others”** (`zones.closeOthers`), **“Close to the right”** (`zones.closeToRight`), **“Close all”** (`zones.closeAll`).
- **Outputs / side effects:** On confirm the tile is removed from the layout tree and `$sessionTiles`; the session itself is NOT stopped or deleted and stays in the sidebar. On cancel nothing changes.
- **Config / env:** n/a
- **Edge cases / guards:** A quiet (idle, unblocked) tile closes with no dialog at all. A tile with no resolvable `runtimeId` reads as quiet and closes silently. Only one confirmation can be pending at a time (single atom), so closing a second running tab while the dialog is open retargets it.
- **Rebuild notes:** Minimum: gate close on a three-flag busy predicate, hold the pending id in one atom, mount the dialog once at the root. A better version would offer "Close and stop" as a second action and remember a "don't ask again" preference per session.

### Voice recording — "Could not read recorded audio"  `id: gapfill-desktop-b-1-r0.voice-audio-read`
- **Surface:** Desktop app
- **Where:** Composer dictation / voice recording (the mic button and the voice conversation pill) — raised while turning the recorded blob into a data URL before upload/transcription.
- **What it does:** Surfaces a clear error when the browser's `FileReader` cannot turn the recorded audio blob into a base64 data URL, instead of failing silently or sending an empty prompt.
- **How it works:** `blobToDataUrl(blob)` (`apps/desktop/src/app/session/hooks/use-prompt-actions/utils.ts:23-36`) wraps `new FileReader()` in a promise: `readAsDataURL(blob)`, resolve on `load` when `typeof reader.result === 'string'`, otherwise `reject(new Error(translateNow('desktop.audioReadFailed')))` (`utils.ts:31`); the `error` listener rejects with `reader.error || new Error(translateNow('desktop.audioReadFailed'))` (`utils.ts:34`). `translateNow` is the non-hook translator, because this runs outside React render. The rejection propagates to the caller's `notifyError(...)`, which uses the caller's own fallback title and this message as the body.
- **Inputs / options:** n/a — no user-facing controls; it is the failure path of the mic/dictation flow.
- **Outputs / side effects:** An error notification whose message is **“Could not read recorded audio”** (`i18n: desktop.audioReadFailed`); no audio is uploaded, no prompt is submitted.
- **Config / env:** Speech-to-text must be enabled at all, or the flow instead reports **“Speech-to-text is disabled in settings.”** (`desktop.sttDisabled`).
- **Edge cases / guards:** Two distinct failure modes map to the same string: a non-string `reader.result` (an `ArrayBuffer` came back) and a genuine `FileReader` error with no `reader.error` populated. A zero-byte recording reads fine and fails later, upstream.
- **Rebuild notes:** Minimum: promise-wrap `FileReader.readAsDataURL` and reject with a translated message on both the wrong-result and error paths. A better version would keep the blob on disk and retry the encode, or hand the raw blob to the uploader so a reader failure never loses the recording.

### "Session unavailable" / "Could not create a new session"  `id: gapfill-desktop-b-1-r0.session-unavailable`
- **Surface:** Desktop app
- **Where:** Every desktop action that needs a live session id and cannot get one: sending the first message of a draft chat, running a slash command from the composer, the "+" / new-session tile creation, and the `/handoff` dispatcher.
- **What it does:** Tells the user that the action could not be attached to a chat because the gateway refused (or failed) to mint a session, instead of leaving the composer looking like the message was sent.
- **How it works:** Four call sites raise the same title/body pair. (1) `useSessionActions` tile creation (`apps/desktop/src/app/session/hooks/use-session-actions/index.ts:753`): after `session.create` (or the route-pinned `requestGatewayForAgent` variant) returns no `stored_session_id`, it first closes the orphan runtime with `session.close`, then `notify({kind:'error', title: copy.sessionUnavailable, message: copy.createSessionFailed})`; the outer `catch` uses `notifyError(error, copy.createSessionFailed)` (`index.ts:791`), which puts the same sentence in the toast *title* and the underlying error text in the body. (2) Submit path (`use-prompt-actions/submit.ts:667`): if `createBackendSessionForSend` throws, it drops the optimistic bubble, releases the busy lock and calls `notifyError(err, copy.sessionUnavailable)` — but only when `targetIsCurrentView()`, so a background tile never toasts over the foreground chat. (3) Same path at `submit.ts:689`: a `null` return with no session-switch drift reason gets `notify({kind:'error', title: copy.sessionUnavailable, message: copy.createSessionFailed})`. (4) `withSlashOutput` (`use-prompt-actions/slash.ts:220`) and the `/handoff` handler (`slash.ts:768`) raise the identical pair when `ensureSessionId(...)` yields nothing. `handoffSession` additionally *returns* `{error: copy.sessionUnavailable, ok: false}` when it has no session id (`use-prompt-actions/index.ts:541`).
- **Inputs / options:** n/a — pure failure feedback with no controls; the user retries by sending again or picking a chat.
- **Outputs / side effects:** Toast title **“Session unavailable”** (`i18n: desktop.sessionUnavailable`), body **“Could not create a new session”** (`i18n: desktop.createSessionFailed`). The optimistic user bubble is removed, the busy/streaming lock is released, and any orphaned runtime session created on the way is closed with `session.close`. Nothing is persisted.
- **Config / env:** n/a — depends on the gateway connection (`useGatewayRequest`) and the active profile.
- **Edge cases / guards:** A `null` create result caused by the user switching sessions mid-create is treated as drift and aborts **silently** (`sessionDriftReason()`), logging `[submit-drift-abort]` instead of toasting. Toasts are suppressed for non-foreground targets via `targetIsCurrentView()`. When the create fails because no provider credential exists, the composer instead shows **“Add a provider credential before sending your first message.”** (`desktop.providerCredentialRequired`).
- **Rebuild notes:** Minimum: one title+body pair reused by every "no session id" path, always paired with rollback of the optimistic message and the busy lock, and always closing an orphan runtime. A better version would auto-retry once on a transient socket error and offer a "Retry" action inside the toast.

### Bare `/` submission — "empty slash command"  `id: gapfill-desktop-b-1-r0.empty-slash-command`
- **Surface:** Desktop app
- **Where:** Composer → type just `/` (or `/` followed only by whitespace/newline) and press Enter. The note appears inline in the transcript as a system message.
- **What it does:** Tells you the slash command was empty, and hands back any text you typed after the bare slash so it is not lost.
- **How it works:** `runSlash(commandText, sessionHint, recordInput)` (`apps/desktop/src/app/session/hooks/use-prompt-actions/slash.ts:1065-1086`) parses with `parseSlashCommand(command)`. When `name` is falsy it (a) restores the composer draft with `setComposerDraft(command)` **if** `command.replace(/^\/+/, '').trim()` is non-empty — the comment at `slash.ts:1071` explains why: the draft was already cleared on submit and slash input never enters the Up-arrow history ring (which derives from sent user messages), so without this the payload after a degenerate slash (`/ text`, `/` + newline) would be lost forever; then (b) `ensureSessionId(sessionHint)` and, if a session exists, `appendSessionTextMessage(sessionId, 'system', copy.emptySlashCommand)` (`slash.ts:1081`), and returns.
- **Inputs / options:** n/a — triggered by the submit action itself (Enter, or the send button) on a degenerate slash string.
- **Outputs / side effects:** A `system` role message reading **“empty slash command”** (`i18n: desktop.emptySlashCommand`) appended to the live transcript, plus the composer draft restored to exactly what was typed. No RPC to the gateway other than the session ensure.
- **Config / env:** n/a
- **Edge cases / guards:** With no session and none creatable, nothing is appended (the draft restore still happens). A truly bare `/` with no trailing text does **not** restore a draft (the trimmed remainder is empty). Multiple leading slashes (`///`) are stripped by the same regex before the emptiness test.
- **Rebuild notes:** Minimum: detect an empty command name, restore the draft when there is payload after the slash, and write a system line into the transcript. A better version would keep the caret in the composer and show the completion popover instead of consuming the turn at all.

### `/help` desktop command catalog — "Desktop commands" group  `id: gapfill-desktop-b-1-r0.desktop-commands-catalog`
- **Surface:** Desktop app
- **Where:** The rendered output of the desktop's command listing (e.g. `/help`) printed inline into the transcript, and the group heading above the command rows.
- **What it does:** Prints the slash commands the desktop app can actually run, grouped into sections, with a trailing count of skill commands and any backend warning.
- **How it works:** `renderCommandsCatalog(catalog, copy)` (`apps/desktop/src/app/session/hooks/use-prompt-actions/utils.ts:472-497`) first narrows the backend catalog to what the desktop supports via `filterDesktopCommandsCatalog(catalog)` (`apps/desktop/src/lib/desktop-slash-commands.ts:649`). Sections come from `desktopCatalog.categories` when the backend supplied any; **when it did not**, one synthetic section is built as `{name: copy.desktopCommands, pairs: desktopCatalog.pairs ?? []}` (`utils.ts:477`) — that fallback name is the string in question. Empty sections are dropped; each remaining section prints `"<name>:"` then one row per pair formatted `` `${cmd.padEnd(18)} ${desc}` ``; sections are joined by a blank line. A tail is appended from `copy.skillCommandsAvailable(skill_count)` and `copy.warningLine(warning)` when present.
- **Inputs / options:** n/a — no flags; the catalog is fetched from the gateway (`commands.catalog`) and warmed on composer mount (`use-slash-completions.ts:78-85`, whose `.catch()` deliberately swallows a warm-up miss so the next keystroke retries).
- **Outputs / side effects:** A text block in the transcript. Group heading **“Desktop commands”** (`i18n: desktop.desktopCommands`) when the backend sent no categories; tail lines **“{count} skill commands available.”** (`desktop.skillCommandsAvailable`) and **“warning: {message}”** (`desktop.warningLine`). With no sections and no pairs the body is the literal, untranslated `No desktop commands available.` (`utils.ts:495`).
- **Config / env:** n/a
- **Edge cases / guards:** Command names are padded to 18 characters, so a longer command name shifts its description right rather than truncating. The `No desktop commands available.` fallback is hard-coded English — a rebuild should translate it.
- **Rebuild notes:** Minimum: filter the backend catalog to locally-dispatchable commands, group them, fall back to a single named group, pad names into a column. A better version would render the catalog as interactive rows (click to insert) rather than preformatted text.

### `/yolo` (desktop) — auto-approve for this chat  `id: gapfill-desktop-b-1-r0.slash-yolo`
- **Surface:** Desktop app
- **Where:** Composer → type `/yolo` and submit. Equivalent to the status-bar YOLO control and to the TUI's `Shift+Tab`.
- **What it does:** Toggles the per-session approval bypass: while armed, tool calls run without asking you to approve each one.
- **How it works:** The `yolo` handler in the desktop slash registry (`apps/desktop/src/app/session/hooks/use-prompt-actions/slash.ts:667-685`) resolves `sid = sessionHint || activeSessionIdRef.current` and computes `next = !$yoloActive.get()`. With **no session id** it only flips the local atom (`setYoloActive(next)`) and toasts — the session-create path applies the armed flag to the first message. With a session it calls `setSessionYolo(requestGateway, sid, next)` (`apps/desktop/src/lib/yolo-session.ts:11-23`), which is `config.set {key:'yolo', session_id, value: enabled ? '1' : '0'}` and reads the authoritative result back as `result?.value === '1'`; the returned truth is written into the transcript as a `system` message. Any throw from that RPC produces the error toast.
- **Inputs / options:** The command takes **no argument** — it is a pure toggle (`/yolo`). The same state is reachable from the status-bar approvals control (`desktop-a.statusbar-approval-mode`).
- **Outputs / side effects:** Local-only arm: success toast **“YOLO armed for this chat”** (`i18n: desktop.yoloArmed`) when turning on, or **“YOLO off”** (`desktop.yoloOff`) when turning off. Session-bound toggle: a transcript `system` line **“YOLO on for this session”** / **“YOLO off for this session”** (`desktop.yoloSystem`, a function of the resolved active flag). Failure: an error toast titled **“YOLO”** (`desktop.yoloTitle`) with the body **“Could not toggle YOLO”** (`i18n: desktop.yoloToggleFailed`). Server-side, `config.set` persists `yolo` for that session.
- **Config / env:** Gateway config key `yolo` scoped by `session_id`; mirrors the CLI `--yolo` flag and the approvals policy documented in `security.md`.
- **Edge cases / guards:** The local atom is flipped **optimistically** only on the no-session path; on the session path the atom is not touched and the backend's echoed value wins, so a rejected toggle cannot leave the UI claiming YOLO is on. The failure toast has no retry — re-run `/yolo`.
- **Rebuild notes:** Minimum: one toggle command, per-session persistence through the config RPC, echo the server's value into the transcript, and a local-only arm for a draft chat. A better version would show the armed state in the composer itself and auto-disarm after N tool calls or on session end.

### `/profile` (desktop) — choose the profile new chats open in  `id: gapfill-desktop-b-1-r0.slash-profile`
- **Surface:** Desktop app
- **Where:** Composer → `/profile` (status) or `/profile NAME` (switch).
- **What it does:** Points the **next** new chat (and the current empty draft) at another profile's backend, without relaunching the app. It does not move an existing conversation.
- **How it works:** The `profile` handler (`apps/desktop/src/app/session/hooks/use-prompt-actions/slash.ts:781-818`) reads `current = normalizeProfileKey($activeGatewayProfile.get())`. With no argument it toasts the status string and returns. With an argument it calls `getProfiles()`, finds `profiles.find(p => p.name === target)` (exact match, case-sensitive), and on a hit: `$newChatProfile.set(normalizeProfileKey(match.name))`, `await ensureGatewayProfile(key)`, `captureNewChatSource()` (records which socket the swap landed on — `null` on the v1 profile path — so a draft's owner matches the socket that will mint it), then a success toast. Any throw is caught by `notifyError(err, copy.setProfileFailed)` (`slash.ts:816`).
- **Inputs / options:** `/profile` with no argument → status. `/profile NAME` → switch. Profile names are completed by the backend catalog; the comparison against `profiles[].name` is exact.
- **Outputs / side effects:** Status toast **“Profile: {current}. Use /profile <name> or the "New session" picker to start a chat in another profile.”** (`desktop.profileStatus`). Unknown name → error toast titled **“Unknown profile”** (`desktop.unknownProfile`) with body **“No profile named "{target}". Available: {available}”** (`desktop.noProfileNamed`). Success → **“New chats will use profile {name}.”** (`desktop.newChatsProfile`). Failure of the lookup/swap → an error toast whose title is **“Failed to set profile”** (`i18n: desktop.setProfileFailed`) and whose body is the underlying error text (that is what `notifyError(error, fallback)` does — `apps/desktop/src/store/notifications.ts:192-201`). Renderer state `$newChatProfile` changes; the gateway connection for that profile is ensured.
- **Config / env:** Profiles come from the gateway (`getProfiles()`); the active profile lives in `$activeGatewayProfile`, the pending choice in `$newChatProfile`.
- **Edge cases / guards:** A profile is **per-session**, so an existing thread cannot change profile mid-stream — the comment at `slash.ts:778` is explicit about this. Branching deliberately stays on the parent thread's owning profile, not `$newChatProfile`.
- **Rebuild notes:** Minimum: status/switch argument split, exact-name lookup with an "available" list in the error, set a pending-profile atom, ensure the connection before returning. A better version would offer fuzzy matching plus a picker overlay, and would show the pending profile in the composer until the next chat consumes it.

### "Stop failed" — interrupt the running turn  `id: gapfill-desktop-b-1-r0.stop-failed`
- **Surface:** Desktop app
- **Where:** The composer stop button (and the same verb on a session tile / tab). Failure feedback for both.
- **What it does:** Reports that the request to interrupt the currently running turn did not reach the agent, so the turn may still be running.
- **How it works:** Two implementations of the same verb. Foreground: `cancelRun` in `apps/desktop/src/app/session/hooks/use-prompt-actions/index.ts:~725-755` first clears this session's pending prompts (`clearAllPrompts(sessionId)`, `clearClarifyRequest(undefined, sessionId)`) — the comment explains why: stop ends the turn, so a dead clarify/approval/sudo/secret panel and the sidebar "needs input" dot must not linger and accept an answer the backend will reject — then calls `withSessionNotFoundResume(sessionId, storedId, liveId => requestGateway('session.interrupt', {session_id: liveId}), {requestGateway, onRecovered})`, releasing the busy lock in both the success and failure branches; the catch calls `notifyError(err, copy.stopFailed)` (`index.ts:753`). Errors: **“Image preview failed”** (`i18n: desktop.imagePreviewFailed`) as a `notifyError` title when the thumbnail cannot be generated; an error toast titled **“Image attach”** (`desktop.imageAttach`) with body **“Failed to write image to disk.”** (`i18n: desktop.imageWriteFailed`) when the temp write returns no path; **“Image attach failed”** (`i18n: desktop.imageAttachFailed`) as a `notifyError` title when the attach throws; a warning titled **“Clipboard”** (`desktop.clipboard`) with body **“No image found in clipboard”** (`i18n: desktop.noClipboardImage`); and **“Clipboard paste failed”** (`desktop.clipboardPasteFailed`) on a paste exception. The drop overlay reads **“Drop files”** (`desktop.dropFiles`) / **“Drop files to attach”** (`composer.dropFiles`).
- **Config / env:** Requires the preload bridge methods `saveImageBuffer` and `saveClipboardImage`; attachment size limits are enforced upstream (see the "too large to upload to the remote gateway" wrapper at `use-prompt-actions/utils.ts:458-470`).
- **Edge cases / guards:** A failed preview is deliberately **not** fatal — the attachment stays and only the thumbnail is missing. Non-image and empty blobs are dropped silently (return `false`) so a text paste is not reported as an image failure. `silent: true` suppresses the "no image in clipboard" warning for the generic paste path.
- **Rebuild notes:** Minimum: attach the pill first, generate the preview asynchronously and bind it by a stable occurrence token, keep only a bounded thumbnail in memory, and give each failure (preview / write / attach / clipboard) its own message. A better version would deduplicate identical images, show upload progress per attachment, and re-encode oversized images client-side before hitting the gateway limit.

### `/handoff` (desktop) — hand this chat to a messaging platform  `id: gapfill-desktop-b-1-r0.slash-handoff`
- **Surface:** Desktop app
- **Where:** Composer → `/handoff` (no argument) or `/handoff PLATFORM`. The platform names are completed inline in the slash popover from the backend's `_handoff_completions`, so there is no picker overlay.
- **What it does:** Asks the separate `hermes gateway` process to move this conversation to a messaging platform (Telegram, etc.) so you can continue it there, and reports progress/success/failure.
- **What it does not do:** The desktop never performs the transfer itself — it only writes the request and polls for the outcome.
- **How it works:** The `handoff` slash handler (`apps/desktop/src/app/session/hooks/use-prompt-actions/slash.ts:756-776`) trims the argument; **empty** → `notify({kind:'success', message: copy.handoff.pickPlatform})` and return (`slash.ts:760`). No session id → the "Session unavailable / Could not create a new session" pair (`slash.ts:768`). Otherwise `handoffSession(platform, {sessionId: sid})`, and a non-ok result is written into the transcript as a `system` message (wrapped by `slashStatusText(command, error)` when `recordInput`). `handoffSession(platform, options)` (`use-prompt-actions/index.ts:533-609`) normalises the platform, reports `onProgress?.('pending')`, calls `handoff.request {platform, session_id}`, then **block-polls** `handoff.state {session_id}` every 800 ms until a 60 s deadline: each state change fires `onProgress(state)`; `completed` → `markCompleted()`; `failed` → `{error: record.error || copy.handoff.failed(target), ok:false}`; a throwing poll simply `continue`s. On deadline it calls `handoff.fail {error: copy.handoff.timedOut, session_id}` — and if that cleanup reports the handoff actually completed in the meantime, it still succeeds; otherwise it returns the timeout error. `markCompleted()` appends a `system` transcript line and toasts.
- **Inputs / options:** `/handoff` (no argument) → the pick-a-destination prompt. `/handoff PLATFORM` → run it. The optional `onProgress(state)` callback (used by callers to show `pending` → … → `completed`). Poll interval 800 ms, deadline 60 000 ms, both hard-coded.
- **Outputs / side effects:** No-argument prompt: a success-kind toast reading **“Choose a destination”** (`i18n: desktop.handoff.pickPlatform`). Success: transcript `system` line **“↻ Handed off to {platform} — resume here anytime.”** (`desktop.handoff.systemNote`) plus a success toast **“Handed off to {platform}. Resume here anytime.”** (`desktop.handoff.success`). Failure: **“Handoff failed: {error}”** (`desktop.handoff.failed`). Timeout: the error **“Timed out waiting for the gateway. Is `hermes gateway` running?”** (`i18n: desktop.handoff.timedOut`) — sent to the gateway as the `handoff.fail` reason AND returned to the caller for display. Server-side the gateway performs the actual transfer.
- **Config / env:** Gateway RPCs `handoff.request`, `handoff.state`, `handoff.fail` (documented gateway-side in `tui.md`). `/handoff` is `cli_only` on the backend, which is exactly why it must not reach `slash.exec` (comment at `slash.ts:753-756`).
- **Edge cases / guards:** Polling errors are swallowed and retried rather than failing the handoff — only the deadline ends the loop. The `handoff.fail` cleanup is itself `.catch(() => null)`, and a `completed` state coming back from it converts a would-be timeout into a success. An empty platform string after normalisation returns `copy.handoff.failed('')`.
- **Rebuild notes:** Minimum: write the request, poll state on a fixed interval with a deadline, always send a fail/cleanup on timeout and honour a late completion, and report progress through a callback. A better version would use a server push (the event stream) instead of an 800 ms poll and would offer to open the destination app once the transfer lands.
