# Gap-fill (round 0, area web-a): Files page row identity, accessible-name templates and the default browsable root

This shard closes the round-0 coverage gaps around the web dashboard Files page (`/files`,
`web/src/pages/FilesPage.tsx`): the per-row *accessible-name* templates (`Open <name>` /
`Download <name>` / `Delete <name>`) with their literal live instances, and the fact that the
default browsable root is the dashboard process's own home directory — which is why the live
listing contains `.ssh`, `.aws`, `.gitconfig` and `.claude.json`. The page's layout, toolbar,
dialogs, toasts, error banner and REST contract stay in `web-a.md` (`web-a.files.*`); the
sensitive-file denylist itself stays in `web-a.md` (`web-a.api.files-sensitive-filter`) and
`security.md`. Verbatim label enumerations were also appended in place to the existing
`web-a.files.row`, `web-a.files.row.open`, `web-a.files.row.download` and `web-a.files.row.delete`
entries; this file adds the two features those entries do not describe.

### Files row accessible-name templates (`Open <name>` / `Download <name>` / `Delete <name>` / `<name>`)  `id: gapfill-web-a-r0.files.row-aria-templates`
- **Surface:** Web dashboard
- **Where:** `/files` → the file table (`Name | Size | Modified | Actions`) → every entry row's four controls: (1) the name button (icon + truncated text, accessible name = the entry name itself, e.g. `.ccr`, `.launchpadlib`, `.pki`, `.wget-hsts`), (2) the directory-only `FolderOpen` ghost icon button `aria-label={`Open ${entry.name}`}`, (3) the file-only `Download` ghost icon button `aria-label={`Download ${entry.name}`}`, (4) the always-present destructive `Trash2` ghost icon button `aria-label={`Delete ${entry.name}`}`. **No i18n key exists for any of the four** — they are literal English template strings in TSX, so they are identical in every dashboard locale (contrast the confirm dialog's own buttons, which are `i18n: common.delete` / `i18n: common.cancel`).
- **What it does:** Gives each row's three icon-only buttons a screen-reader/automation name built from the filesystem entry name, and makes the name cell itself a button whose label is the raw entry name. This is the only text that distinguishes one row's actions from another's, because the buttons render icons only.
- **How it works:** `web/src/pages/FilesPage.tsx:398-453` maps `listing.entries` (from `GET /api/files`) to one `<div key={entry.path}>` grid row per entry. `:402-414` renders the name button: `onClick={() => (entry.is_directory ? openDirectory(entry) : void downloadFile(entry))}` (`:405`), a `Folder` icon in `text-warning` for directories or a `FileIcon` in `text-text-tertiary` for files (`:407-411`), then `<span className="truncate">{entry.name}</span>` (`:413`) — so the button's accessible name is exactly the entry name and long names are CSS-truncated (the full name is *not* exposed via `title=`). `:419-441` picks the middle action by type: the directory branch (`:420-429`) renders `<Button ghost size="icon" type="button" onClick={() => openDirectory(entry)} aria-label={`Open ${entry.name}`}><FolderOpen /></Button>`; the file branch (`:430-440`) renders the same shape with `onClick={() => void downloadFile(entry)}`, `aria-label={`Download ${entry.name}`}` and `<Download />`. `:441-450` always renders `<Button ghost size="icon" type="button" onClick={() => setPendingDelete(entry)} aria-label={`Delete ${entry.name}`} className="text-destructive hover:text-destructive"><Trash2 /></Button>`. The handlers: `openDirectory` (`:152-156`) sets `currentPath = entry.path` only when `entry.is_directory`, which re-triggers the load effect (`:119-124`) → `GET /api/files?path=…`; `downloadFile` (`:238-246`) returns early for directories, else `api.readFile(entry.path)` → `GET /api/files/read?path=…` → `downloadDataUrl(file.data_url, file.name)` (`:61-68`, synthetic `<a download>` appended to `document.body`, clicked, removed); `setPendingDelete(entry)` opens `DeleteConfirmDialog` (`:511-521`) whose title is the fourth instance of the same template, `` `Delete ${pendingDelete.name}?` `` (`:517`), falling back to `Delete item?` when nothing is pending, with description `This removes the folder and everything inside it.` (directories) or `This removes the file.` (files); confirming runs `confirmDelete()` (`:248-259`) → `api.deleteFile(pendingDelete.path, pendingDelete.is_directory)` → `DELETE /api/files` `{path, recursive: is_directory}`. Row order is decided server-side: `hermes_cli/web_server.py:2850` sorts by `(not is_directory, name.lower())` — every directory first, then files, each case-insensitively alphabetical — so the label sequence below is reproducible.
- **Inputs / options:** Per row, four click targets, all `type="button"`, no keyboard shortcut and no context menu: **(a)** name button — label = entry name; **(b)** `Open <name>` (directories only); **(c)** `Download <name>` (files only); **(d)** `Delete <name>` (all rows). Complete list of the instances rendered by the live install browsing its default root `/root` (Playwright crawl `hermes_inv/web_crawl/_files.json`, state `initial`; cross-checked against live `GET /api/files`) — 22 rows, 15 directories then 7 files: name buttons `.aws`, `.bun`, `.cache`, `.cargo`, `.ccr`, `.claude`, `.config`, `.gradle`, `.hermes`, `.launchpadlib`, `.local`, `.npm`, `.pki`, `.rustup`, `.ssh`, `.bashrc`, `.boto`, `.claude.json`, `.gitconfig`, `.profile`, `.wget-hsts`, `.zshrc`; open buttons `Open .aws`, `Open .bun`, `Open .cache`, `Open .cargo`, `Open .ccr`, `Open .claude`, `Open .config`, `Open .gradle`, `Open .hermes`, `Open .launchpadlib`, `Open .local`, `Open .npm`, `Open .pki`, `Open .rustup`, `Open .ssh`; download buttons `Download .bashrc`, `Download .boto`, `Download .claude.json`, `Download .gitconfig`, `Download .profile`, `Download .wget-hsts`, `Download .zshrc`; delete buttons `Delete .aws`, `Delete .bun`, `Delete .cache`, `Delete .cargo`, `Delete .ccr`, `Delete .claude`, `Delete .config`, `Delete .gradle`, `Delete .hermes`, `Delete .launchpadlib`, `Delete .local`, `Delete .npm`, `Delete .pki`, `Delete .rustup`, `Delete .ssh`, `Delete .bashrc`, `Delete .boto`, `Delete .claude.json`, `Delete .gitconfig`, `Delete .profile`, `Delete .wget-hsts`, `Delete .zshrc`; and the matching dialog titles `Delete .aws?`, `Delete .bun?`, `Delete .cache?`, `Delete .cargo?`, `Delete .ccr?`, `Delete .claude?`, `Delete .config?`, `Delete .gradle?`, `Delete .hermes?`, `Delete .launchpadlib?`, `Delete .local?`, `Delete .npm?`, `Delete .pki?`, `Delete .rustup?`, `Delete .ssh?`, `Delete .bashrc?`, `Delete .boto?`, `Delete .claude.json?`, `Delete .gitconfig?`, `Delete .profile?`, `Delete .wget-hsts?`, `Delete .zshrc?`. Above the rows sits the non-templated `..` parent button (`:374-388`).
- **Outputs / side effects:** `Open <name>` → client-side navigation + `GET /api/files?path=<dir>` (no URL change: `currentPath` is React state, so the browser Back button does **not** go up a directory). `<name>` on a directory → identical. `Download <name>` and `<name>` on a file → `GET /api/files/read?path=…` returning `{name, path, size, mime_type, data_url, root, locked_root, can_change_path}` and a browser download of the decoded blob; failure toasts `` `Download failed: ${e}` ``. `Delete <name>` → opens the dialog only; confirming issues `DELETE /api/files` (`shutil.rmtree` for directories, `Path.unlink` for files, `web_server.py:3108-3117`), toasts `Deleted`, then reloads the listing; failure toasts `` `Delete failed: ${e}` ``.
- **Config / env:** none of these four labels is configurable. Which of (b)/(c) appears is decided by `entry.is_directory` in the `GET /api/files` payload; the row set itself is governed by `HERMES_DASHBOARD_FILES_ROOT` and `HERMES_HOME` (see the next entry).
- **Edge cases / guards:** Two entries whose names differ only by case produce two buttons with the same normalised label but distinct `key={entry.path}`. An entry name containing a template-breaking character is inserted literally (React escapes it, so no injection). Names hidden by the sensitive-path filter (`_is_sensitive_path`, `web_server.py:2296-2316`) never reach the row renderer, so there is never an `Open .env` / `Download auth.json` button. The delete button is rendered even for entries the server will refuse (`400 Cannot delete the managed files root`, `400 Cannot delete the filesystem root`), so the guard is server-side only. Icon-only buttons have no visible text and no `title=`, so a sighted user must rely on the icons (`FolderOpen`, `Download`, `Trash2`); a mechanical string checker sees these labels only through `aria-label`.
- **Rebuild notes:** Minimal spec: for each listing entry render `button[aria-label="Open "+name]` or `button[aria-label="Download "+name]` plus `button[aria-label="Delete "+name]`, and make the name cell a button with the bare name as its label; keep the delete confirm title `Delete <name>?`. A better version would (a) run these four strings through the i18n layer as parameterised keys (`files.row.open`/`download`/`delete` with a `{name}` placeholder) instead of hard-coded English, (b) add a `title=` with the full path so truncated names remain identifiable, and (c) route the row-name click through an explicit "open/preview" affordance rather than silently starting a base64 download.

### Default browsable root = the dashboard user's home directory (unlocked)  `id: gapfill-web-a-r0.files.default-root-home`
- **Surface:** Web dashboard
- **Where:** `/files` on first load (no `?path=`), and the header path badge / `Path` input that then show it — on the live install the badge and input read `/root` and the rows are that user's dotfiles.
- **What it does:** When no managed-files root is forced, the Files page opens on `Path.home()` of the process running the dashboard and lets the operator type any absolute path, so the browser can list, download, upload into and delete anything that user can — including `.ssh`, `.aws`, `.gitconfig` and `.claude.json`.
- **How it works:** `_managed_files_policy(request)` (`hermes_cli/web_server.py:2631-2646`) resolves in three branches, in order: (1) `HERMES_DASHBOARD_FILES_ROOT` set → `ManagedFilesPolicy(default_path=root, locked_root=root, can_change_path=False)`; (2) `_default_hermes_root_is_opt_data()` (`:2579-2590`, the container/hosted layout where the Hermes root resolves to `/opt/data` = `_HOSTED_MANAGED_FILES_ROOT`, `:2208`) → locked to `/opt/data`; (3) **otherwise** `home = _canonical_path(Path.home())` → `ManagedFilesPolicy(default_path=home, locked_root=None, can_change_path=True)`. With `locked_root=None`, `_resolve_managed_path` (`:2650-2685`) only rejects a relative path (`400 Path must be absolute`) and any `..` component (`400 Path cannot contain '..'`) — the `_path_is_under(root, resolved)` containment check at `:2681` is skipped, so **there is no upper boundary**; `_managed_response_meta` (`:2688-2695`) then returns `{"root": null, "locked_root": null, "can_change_path": true}`, which is what makes the client render the editable path bar (`FilesPage.tsx:276-294`) instead of the read-only line. Listing (`:2830-2860`) drops only entries matching `_is_sensitive_path` and sorts directories first. Live proof: `GET /api/files` on the running dashboard returns `{"path":"/root","parent":"/","root":null,"locked_root":null,"can_change_path":true}` with 22 entries.
- **Inputs / options:** No UI control selects the root — it is chosen entirely by environment. The user-facing consequences are the `Path` input + `GO` button being present (unlocked) versus a read-only path line (locked), and the `..` row existing all the way up to `/` (the server omits `parent` only at the filesystem root or at `locked_root`, `:2853-2855`).
- **Outputs / side effects:** The initial `GET /api/files` (no `path`) returns the home directory listing; the header badge and the `Path` input are seeded with the server-canonicalised path. Every subsequent action (upload, mkdir, download, delete) targets real paths under whatever directory the operator navigated to.
- **Config / env:** `HERMES_DASHBOARD_FILES_ROOT` (`_MANAGED_FILES_ROOT_ENV`, `web_server.py:2191`) — set it to lock and default the root and hide the path bar; `HERMES_HOME` — when the installation's Hermes root resolves to `/opt/data` the browser is locked there. `HOME` (via `Path.home()`) decides the unlocked default. No dotted `config.yaml` key participates.
- **Edge cases / guards:** The only read-side redaction is the sensitive-path filter (`.env`/`.env.*`/`.envrc`, `auth.json`, `auth.lock`, `credentials`, `config.yaml`, `.anthropic_oauth.json`, `google_token.json`, `google_oauth_pending.json`, `google_oauth.json`, `webhook_subscriptions.json`, `bws_cache.json`, `bws_cache.enc.json`, `.git-credentials`, plus any path containing a `mcp-tokens` or `pairing` component — `web_server.py:2244-2316`). That denylist does **not** cover `.ssh`, `.aws`, `.kube`, `.gnupg`, `.docker`, `.npmrc`, `.netrc` or `.claude.json`, so on the live install the browser shows `Open .ssh` / `Delete .ssh` and `Download .claude.json` / `Download .gitconfig` buttons: private keys are listable and (per-file) downloadable through `GET /api/files/read`, and `Delete .ssh` recursively `shutil.rmtree`s the key directory after one confirm dialog. That is strictly wider than the agent-side file-safety policy documented in `security.md` (which denies `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.docker`, `~/.azure`, `~/.config/gh`, `~/.config/gcloud` as write prefixes). Mitigations that do apply: the dashboard's own auth gate (session token / OAuth) protects every `/api/files*` route, 100 MiB per-file cap (`_MANAGED_FILE_MAX_BYTES`, `:2192`), `403 Path outside managed files root` only in the locked modes, and `400 Cannot delete the managed files root` / `400 Cannot delete the filesystem root` on delete. `/api/files` is not profile-scoped, so the header profile switcher never changes the root.
- **Rebuild notes:** Minimal spec: a policy object `{default_path, locked_root, can_change_path}` derived from env, a resolver that canonicalises + rejects `..`/relative paths and (when locked) enforces containment, and a listing endpoint that filters a credential denylist and sorts directories first. A better version would default to an explicit workspace directory instead of `$HOME`, require an opt-in env var before allowing arbitrary absolute paths, extend the denylist to credential *directories* (`.ssh`, `.aws`, `.gnupg`, `.kube`, `.docker`, `.config/gh`, `.config/gcloud`) on the read **and** write paths, and require re-authentication for recursive deletes.

## Handoffs
- `security.md` — the managed-files read denylist is documented there and in `web-a.md` (`web-a.api.files-sensitive-filter`), but neither states that credential *directories* such as `~/.ssh` / `~/.aws` remain fully browsable, downloadable and deletable through the dashboard; the security shard may want to record that as an explicit finding.
- `desktop-a.md` / `web-shell.md` — the streaming `GET /api/files/download` and `GET /api/files/stream` routes (unused by this page) belong to the desktop/media shards.
