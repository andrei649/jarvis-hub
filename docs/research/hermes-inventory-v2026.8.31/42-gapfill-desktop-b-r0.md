# Gap-fill — Desktop app (area desktop-b, round 0)

Scope: the desktop-app machinery behind composer voice input and profile portability that the
`desktop-b` shard's button-level entries reference but never document — the three microphone hooks
(`use-mic-recorder`, `use-voice-recorder`, `use-voice-conversation`) with their complete notification
copy, the native "Input needed" OS notification raised by the gateway input-request family, and the
profile export/import bundle flows (`store/profile-share.ts`) with their success/failure toasts.
Buttons and pills that *trigger* these (Voice pill, Dictation button, profile rail, ⌘K rows) stay in
`desktop-b.md`; approval/turn-done native notifications stay in `desktop-b.md` / `gapfill-desktop-a-r0.md`.

---

### Composer microphone recorder (`useMicRecorder`)  `id: gapfill-desktop-b-r0.mic-recorder`
- **Surface:** Desktop app
- **Where:** No pixels of its own — it is the capture engine under every composer voice affordance: the **“Voice dictation”** button, the **“Start voice conversation”** button/pill, and the `composer.voice` keybind **“Start / stop voice conversation”**. `apps/desktop/src/app/chat/composer/hooks/use-mic-recorder.ts:1-295`.
- **What it does:** Opens the microphone, records a clip with `MediaRecorder`, meters the live input level, and can auto-stop the clip on silence. Every failure path is turned into an `Error` whose message is a translated, human sentence.
- **How it works:** `useMicRecorder(copy)` returns `{handle: {start, stop, cancel}, level, recording}` (`:181-295`). `start()` (`:172`) checks the runtime (`navigator.mediaDevices?.getUserMedia` and `MediaRecorder`, `:176`), asks Electron for OS mic permission via `window.hermesDesktop.requestMicrophoneAccess()` (`:178`, preload `apps/desktop/electron/preload.ts:226` → `ipcMain.handle('hermes:requestMicrophoneAccess')` at `apps/desktop/electron/main.ts:15500`, which on non-macOS returns `true` and on macOS calls `systemPreferences.askForMediaAccess('microphone')`), then `getUserMedia({audio: {echoCancellation: true, noiseSuppression: true}})` (`:187`). MIME negotiation walks the list `audio/webm;codecs=opus` → `audio/webm` → `audio/mp4` → `audio/ogg;codecs=opus` → `audio/ogg` → `audio/wav`, taking the first `MediaRecorder.isTypeSupported` hit (`:194-197`). The level meter (`startMeter`, `:96`) builds an `AudioContext` (with `webkitAudioContext` fallback), an `AnalyserNode` with `fftSize = 256`, computes RMS over the centred time-domain bytes and normalises as `min(1, rms/42)` on every `requestAnimationFrame` (`:120-138`). `micError(error, copy)` (`:53`) maps `DOMException.name` to copy: `NotAllowedError`/`SecurityError` → `microphonePermissionDenied`, `NotFoundError`/`DevicesNotFoundError` → `noMicrophone`, `NotReadableError`/`TrackStartError` → `microphoneInUse`, `OverconstrainedError` → `microphoneConstraintsUnsupported`, any other `Error` passes through unchanged, and anything else → `microphoneStartFailed`.
- **Inputs / options:** `MicRecorderOptions` passed to `start()`: `onLevel?(level: number)`, `onError?(error: Error)`, `onSilence?()`, `silenceLevel?` (normalised speech threshold), `silenceMs?` (post-speech silence before auto-stop), `idleSilenceMs?` (silence before ever hearing speech). `MicRecorderErrorCopy` (`:20-28`) supplies the seven translated sentences: **“Microphone access denied.”** (`i18n: notifications.voice.microphoneAccessDenied`), **“Microphone constraints are not supported by this device.”** (`i18n: notifications.voice.microphoneConstraintsUnsupported`), **“Microphone is already in use by another app.”** (`i18n: notifications.voice.microphoneInUse`), **“Microphone permission was denied.”** (`i18n: notifications.voice.microphonePermissionDenied`), **“Could not start microphone recording.”** (`i18n: notifications.voice.microphoneStartFailed`), **“This runtime does not support microphone recording.”** (`i18n: notifications.voice.microphoneUnsupported`), **“No microphone was found.”** (`i18n: notifications.voice.noMicrophone`) — all defined at `apps/desktop/src/i18n/en.ts:166-184`. Handle methods: `start(options?)`, `stop()` → `Promise<MicRecording | null>`, `cancel()` (drops the clip and detaches all three MediaRecorder handlers before stopping).
- **Outputs / side effects:** `stop()` resolves `{audio: Blob, durationMs: number, heardSpeech: boolean}` (`MicRecording`, `:15-19`) or `null` when no chunks were captured / the recorder was already inactive. Opens and closes the OS capture device; every path runs `cleanup()` which cancels the animation frame, closes the `AudioContext`, stops every `MediaStreamTrack`, and resets `level` to 0 and `recording` to false. Errors are **thrown** (start path) or handed to `options.onError` (mid-recording `recorder.onerror`) — this hook never toasts on its own.
- **Config / env:** No config keys of its own; the callers pass `voice.max_recording_seconds` and gate on `stt.enabled`. macOS requires the `NSMicrophoneUsageDescription` entitlement (**“Hermes uses the microphone for voice input and voice conversations.”**).
- **Edge cases / guards:** `start()` is a no-op if a recorder already exists (one mic owner at a time). An Electron permission refusal (`permitted === false`) throws **“Microphone access denied.”** *before* `getUserMedia` is ever called, so the browser prompt never double-fires. A `MediaRecorder` constructor failure stops the freshly-acquired tracks before rethrowing (`:203-206`), so a rejected codec cannot leak an open mic. The meter is best-effort: a thrown `AudioContext` construction only sets `level = 0` (`:141`), recording continues. Silence auto-stop fires **once** per recording (`silenceTriggeredRef`) and only when `silenceLevel > 0` and an `onSilence` callback exists. An unmount always runs `cleanup()` (`:88`).
- **Rebuild notes:** Minimal spec — a hook that owns exactly one `MediaStream` + `MediaRecorder`, exposes start/stop/cancel, resolves a `{blob, durationMs, heardSpeech}` on stop, meters RMS for a level bar, and translates `DOMException.name` into one of seven human sentences. Better version: expose device enumeration/selection (there is no input-device picker on the desktop side today, unlike `wake_word.input_device` on the backend), detect an all-zero stream (a "working" but silent device, the macOS failure mode the backend already detects) and surface it as its own error, and negotiate Opus bitrate for slow relays.

### Composer push-to-talk recorder (`useVoiceRecorder`)  `id: gapfill-desktop-b-r0.voice-recorder`
- **Surface:** Desktop app
- **Where:** Behind the composer **“Voice dictation”** button (`composer.voiceDictation`, `controls.tsx:398`) and the voice menu's dictation checkbox. `apps/desktop/src/app/chat/composer/hooks/use-voice-recorder.ts:1-116`, wired at `apps/desktop/src/app/chat/composer/hooks/use-composer-voice.ts:69-74`.
- **What it does:** One-shot dictation: press to record, press again (or hit the cap) to stop, transcribe the clip, and insert the text into the composer. It is not a loop — one clip, one transcript.
- **How it works:** `dictate()` (`:101`) is the single toggle: recording → `stop()`, `idle` → `start()`, anything else ignored. `start()` (`:80`) refuses when no `onTranscribeAudio` is wired, then calls `handle.start({onError})`, stamps `startedAtRef`, sets status `recording`, ticks `elapsedSeconds` every 250 ms, and arms a hard cap timer of `clamp(trunc(maxRecordingSeconds), 1, 600)` seconds (`:93-94`). `stop()` (`:46`) clears timers, awaits `handle.stop()`, and — when a clip came back and a transcriber exists — flips status to `transcribing`, trims the transcript, then either notifies "no speech" or calls `onTranscript(text)`; `finally` always returns status to `idle` and calls `focusInput()`. Status type `VoiceStatus` is `idle | recording | transcribing`; `voiceActivityState` is `{elapsedSeconds, level, status}`.
- **Inputs / options:** Hook options (`:10-15`): `maxRecordingSeconds: number`, `onTranscribeAudio?: (audio: Blob) => Promise<string>`, `focusInput: () => void`, `onTranscript: (text: string) => void`. Returned API: `dictate()`, `voiceActivityState`, `voiceStatus`. Toast copy it raises: warning **“No speech detected”** (`i18n: notifications.voice.noSpeechDetected`) with body **“Try recording again.”** (`i18n: notifications.voice.tryRecordingAgain`) at `:68`; warning **“Voice unavailable”** (`i18n: notifications.voice.unavailable`) with body **“Voice transcription is not available yet.”** (`i18n: notifications.voice.transcriptionUnavailable`) at `:82`; error **“Voice transcription failed”** (`i18n: notifications.voice.transcriptionFailed`) at `:73`; error **“Voice recording failed”** (`i18n: notifications.voice.recordingFailed`) at `:88` (mid-recording `onError`) and `:97` (start threw).
- **Outputs / side effects:** Inserts the trimmed transcript into the composer via `onTranscript` (wired to `insertText`), refocuses the composer, and pushes toasts into the shared notification store (`@/store/notifications` — `notify` / `notifyError`). Network: the transcription call itself (client-direct to the profile's STT provider, else relayed through the gateway).
- **Config / env:** `voice.max_recording_seconds` (default `120`, read in `apps/desktop/src/app/session/hooks/use-hermes-config.ts:133`, clamped to ≤ 600 s here) and `stt.enabled` (`use-hermes-config.ts:134`) — when STT is off, `transcribeVoiceAudio` throws **“Speech-to-text is disabled in settings.”** (`desktop.sttDisabled`, `use-prompt-actions/index.ts:651-655`).
- **Edge cases / guards:** With no `onTranscribeAudio` prop at all, `start()` never opens the mic — it warns **“Voice unavailable”** / **“Voice transcription is not available yet.”** instead (this is why `latestOptional()` must preserve the handler's *optionality*, see `desktop-b.composer-conversation-pill` / `desktop-b.contrib-latest-actions`). A clip that returns `null` (nothing captured) silently returns to `idle`. A transcript that trims to empty raises the warning rather than inserting whitespace. Timers are cleared on unmount (`:44`). Cap timer is per-recording and re-armed on each start.
- **Rebuild notes:** Minimal spec — `{status, elapsed, level}` state machine over the mic recorder, a hard duration cap, "empty transcript is a warning, not an error", and refocus-on-finish. Better version: stream partial transcripts while recording (so the user sees words appear), keep the failed clip so a retry does not lose the utterance, and offer an undo that removes an inserted transcript in one keystroke.

### Composer voice conversation loop (`useVoiceConversation`)  `id: gapfill-desktop-b-r0.voice-conversation`
- **Surface:** Desktop app
- **Where:** Behind the composer **“Start voice conversation”** button, the voice menu's first row, the `composer.voice` keybind (**“Start / stop voice conversation”**, `ctrl+b` on macOS), and the live **Voice conversation pill**. `apps/desktop/src/app/chat/composer/hooks/use-voice-conversation.ts:1-736`, wired at `apps/desktop/src/app/chat/composer/hooks/use-composer-voice.ts:138-159`.
- **What it does:** Runs the hands-free loop — listen → transcribe → submit → speak the reply → listen again — with full-duplex barge-in so the user can talk over generation or playback, and a spoken stop word that ends the conversation.
- **How it works:** A five-state machine `ConversationStatus = idle | listening | transcribing | thinking | speaking` (`:19`). `start()` (`:576`) resets mute, drops any speech session, consumes the pending reply, and calls `startListening()`. `startListening()` (`:243`) awaits `beforeMicOpen()` (the wake-listener release barrier) and opens the mic with VAD tuning that mirrors `tools.voice_mode`: `silenceLevel: 0.075`, `silenceMs: 1_250`, `idleSilenceMs: 12_000` (`:264-267`), plus a 60 s hard turn timeout (`:283`). `handleTurn(forceTranscribe?)` (`:137`) stops the mic, discards clips with `heardSpeech === false` unless forced, transcribes, checks `isVoiceStopCommand()` (`@/lib/voice-stop-word`), and otherwise submits. Reply playback: `openLiveSpeech()` (`:479`) opens a `startSpeechStream({source: 'voice-conversation'})` session and feeds it new reply text on a 150 ms timer (`feedSpeechSession`, `:406`); if no streaming backend exists it falls back to `awaitFallbackSpeech()` (`:432`) which polls until the reply completes then calls `playSpeechText()`. `ensureBargeMonitor()` (`:378`) arms `monitorSpeechDuringPlayback` for the whole turn — speech during generation calls `onInterrupt()` (the Stop-button seam) and speech during playback calls `stopVoicePlayback()`; the captured utterance goes to `submitCapturedUtterance()` (`:308`), which waits up to `INTERRUPT_SETTLE_TIMEOUT_MS = 5_000` for `busy` to clear before submitting. Ambient blips play while `status === 'thinking'` (`startThinkingSound`, `:663`).
- **Inputs / options:** Hook options (`:26-41`): `busy: boolean`, `enabled: boolean`, `onFatalError?()`, `onInterrupt?()`, `onStopWord?()`, `onSubmit(text)`, `onTranscribeAudio?(audio)`, `pendingResponse(): {id, pending, text} | null`, `consumePendingResponse()`, `beforeMicOpen?()`. Returned API: `end()`, `level`, `muted`, `start()`, `status`, `stopTurn()`, `toggleMute()`. Keyboard: **Space** (captured on `window`, no modifiers, non-repeat) ends the current listening turn and sends — `stopTurn()` at `:641-654`. Toast copy it raises: warning **“Voice unavailable”** (`i18n: notifications.voice.unavailable`) with body **“Configure speech-to-text to use voice mode.”** (`i18n: notifications.voice.configureSpeechToText`) at `:577-582`; error **“Could not start voice session”** (`i18n: notifications.voice.couldNotStartSession`) at `:257`; error **“Microphone failed”** (`i18n: notifications.voice.microphoneFailed`) at `:242` (mic error mid-session); error **“Voice transcription failed”** (`i18n: notifications.voice.transcriptionFailed`) at `:191` (normal turn) and `:360` (barge-captured utterance); error **“Voice playback failed”** (`i18n: notifications.voice.playbackFailed`) at `:469`.
- **Outputs / side effects:** Submits turns to the agent, plays TTS audio, interrupts in-flight turns, opens/closes the mic, pushes the toasts above, and drives the pill's status announcements. `onFatalError` flips `voiceConversationActive` off (composer wiring at `use-composer-voice.ts:142`), which tears the loop down through the `enabled` effect; `onStopWord` does the same for spoken **“stop”** / **“never mind”** / **“goodbye”** / **“cancel”** / **“that's all”**.
- **Config / env:** `voice.thinking_sound` plus the shared sound mute gate the ambient blips; `stt.enabled` gates `onTranscribeAudio`; TTS provider config governs `startSpeechStream` / `playSpeechText`.
- **Edge cases / guards:** No `onTranscribeAudio` → the loop refuses to start and warns instead of opening a mic it cannot use. `startListening()` re-checks `enabled`/`muted`/`busy`/`status` *after* awaiting the wake barrier, because any of them can flip while waiting (`:311`-style double check at `:255`). One barge monitor owns the mic per turn (`ensureBargeMonitor` is idempotent). A stale 60 s turn timer is cleared before a fresh one is armed, or it would cut a later listen short. External `stopVoicePlayback()` (Stop button, End) is detected via the `$voicePlayback` sequence counter so an explicit stop never auto-starts the next sentence (`:426-430`, `:521-534`). A turn that finishes with no speakable reply (tool-only or error) resets to `idle` and re-listens (`:700-708`). Muting cancels the live capture immediately; unmuting re-arms only when idle and not busy.
- **Rebuild notes:** Minimal spec — a status machine over the mic recorder plus a TTS session, with (a) VAD auto-stop, (b) whole-utterance stop-word detection, (c) a barge monitor live across *both* generation and playback that captures the interruption from its first syllable, and (d) a monotonically increasing playback sequence so "the user pressed Stop" is distinguishable from "the sentence ended". Better version: local streaming ASR so partial transcripts appear while speaking, per-speaker VAD calibration that survives noisy rooms, and a visible transcript of the conversation the user can scroll and correct.

### Native OS notification — “Input needed”  `id: gapfill-desktop-b-r0.native-input-notification`
- **Surface:** Desktop app
- **Where:** An operating-system notification (Electron `Notification`), not an in-app toast. Raised from the gateway event stream at `apps/desktop/src/app/session/hooks/use-message-stream/gateway-event/input-requests.ts:101`, `:149`, `:218`, `:282`, `:313`.
- **What it does:** Tells the user, while they are away from Hermes (or looking at a different chat), that a session has stopped and is blocked waiting for them — a clarify question, an MCP setup consent, a sudo password, or a skill credential.
- **How it works:** `handleInputRequestEvent()` handles the blocking-input family (`clarify.request`, `clarify.expire`, `mcp.setup.request`, `approval.request`, `sudo.request`, `secret.request`). Four of them call `dispatchNativeNotification({kind: 'input', title: translateNow('notifications.native.inputTitle'), body, sessionId})`: batch clarify (body = every question joined with `" · "`, `:102`), single clarify (body = the question, `:150`), MCP setup consent (body = `reason || server`, `:219`), sudo (body = the generic `notifications.native.inputBody`, `:283`) and secret capture (body = `prompt || env_var ||` that same generic body, `:314`). The store (`apps/desktop/src/store/native-notifications.ts:191`) then applies four gates in order: prefs enabled + this kind enabled, `withinNativeNotifyBaseline()`, `shouldFire()`, and a 1 s dedupe throttle keyed `"{kind}:{sessionId|tag|global}"` (`THROTTLE_MS = 1000`, `:97`). `shouldFire()` (`:130`) treats `approval` and `input` as **attention kinds**: they fire when the app is backgrounded **or** when the request belongs to a session that is not the active one — unlike completion kinds, which need both. "Backgrounded" is `document.hidden || !document.hasFocus()` (`:117`). The surviving call reaches Electron through `window.hermesDesktop.notify({...})`.
- **Inputs / options:** No user controls at the notification itself for this kind (unlike `approval`, which carries the **“Approve”** / **“Reject”** action buttons). Clicking the body focuses the originating session. The kind is user-toggleable: `input` is one of the seven `NATIVE_NOTIFICATION_KINDS` — `approval`, `input`, `turnDone`, `turnError`, `backgroundDone`, `credits`, `plugin` — each default `true` under a master `enabled: true` (`native-notifications.ts:38-49`), flipped by `setNativeNotifyEnabled(enabled)` and `setNativeNotifyKind(kind, on)`.
- **Outputs / side effects:** An OS notification titled **“Input needed”** (`i18n: notifications.native.inputTitle`, `apps/desktop/src/i18n/en.ts:190`) with a body that is the question/prompt text or, when there is none, the generic **“Hermes is waiting for your response.”** (`i18n: notifications.native.inputBody`, `en.ts:191`). `dispatchNativeNotification` returns `true` only when the notification actually reached the OS bridge — callers that register per-notification state must check it or leak on a suppressed notification. The same events also set `needsInput: true` on the session state (which paints the sidebar's **“Needs input”** status) and park the request per-session so a background profile's blocked turn is recoverable.
- **Config / env:** Preferences persist to `localStorage` under the key `hermes:native-notifications` as `{enabled, kinds}` (`STORAGE_KEY`, `native-notifications.ts:36`).
- **Edge cases / guards:** Replayed gateway events for the same kind+session inside 1 s collapse into one notification; the throttle map self-evicts entries older than the window on every dispatch, so it cannot grow. A notification-baseline window right after boot/reconnect suppresses the burst of replayed requests (`withinNativeNotifyBaseline()`). `clarify.request` for an interrupted session returns early and never notifies (`input-requests.ts:38-40`). `clarify.expire` is request-id-correlated so a delayed expiry cannot erase a newer question. Requests without a `request_id` (or without a `question`/`server`) are dropped without a notification.
- **Rebuild notes:** Minimal spec — one dispatcher with per-kind prefs, an "attention kinds break through focus for other sessions" rule, a short dedupe throttle, and a boot baseline; blocking prompts must notify even for background sessions or an agent can hang invisibly. Better version: make the notification actionable for clarify (inline reply / choice buttons the way approval already has Approve/Reject) and coalesce several waiting sessions into one summary notification instead of throttling them away.

### Profile export bundle (“Export…” → “Export profile…”)  `id: gapfill-desktop-b-r0.profile-export-flow`
- **Surface:** Desktop app
- **Where:** Three doors, all funnelling into `runExportProfileFlow()`: the profile pill menu item **“Export…”** (`i18n: profiles.exportMenu`), the command palette row **“Export profile…”** (`profile.export`, `desktop-b.md:1110`), and any future menu. Native save dialog titled **“Export profile…”** (`i18n: profiles.exportProfile`, `apps/desktop/src/i18n/en.ts:1850`). Implementation `apps/desktop/src/store/profile-share.ts:159-187`.
- **What it does:** Writes one profile to a portable `.tar.gz` archive — the CLI's own profile export (config, skills, `SOUL.md`, cron; credentials always excluded) plus a desktop-only appearance/interface overlay — so it can be handed to another machine or another person.
- **How it works:** `runExportProfileFlow(profile?)` normalises the target (defaults to the active profile via `activeProfileKey()` → `normalizeProfileKey($activeGatewayProfile.get())`, `:146-148`), calls `window.hermesDesktop.selectSavePath({title, defaultPath, filters})` and bails to `null` when the bridge is missing or the user cancels. It then calls `exportProfileBundle(target, output)` (`:72`), which builds the overlay with `buildDesktopOverlay(profile)` (`:46`) and hands it to `exportProfileArchive(profile, {extraFiles: {'desktop.json': JSON.stringify(overlay, null, 2)}, output})`. The overlay (`ProfileDesktopOverlay`, version `1`) carries `skin` (`skinPref.resolve(key)`), `mode` (`modePref.resolve(key)`), the full definition of any **non-built-in** theme the skin points at (`themes[name]`, so the receiver's picker can resolve it — built-ins resolve by name), `profileColor` (the rail colour, or `null`) and `layoutTree` (`$layoutTree.get()` — global by design, one window layout). Only **paths** cross the renderer↔backend boundary, never bytes: the native dialog and the backend share a filesystem for local and pooled backends (module comment, `:11-13`).
- **Inputs / options:** `profile?: string` (omit for the active profile). Save dialog: default filename `` `${target}.tar.gz` ``; file-type filter `ARCHIVE_FILTERS = [{extensions: ['tar.gz', 'tgz'], name: 'Hermes profile'}]` (`:155`).
- **Outputs / side effects:** Writes the archive to the chosen path and returns it. On success, a success toast titled **“Profile exported”** (`i18n: profiles.exported`, `en.ts:1852`) whose message body is the archive path (`:179`). On failure, `notifyError(error, translateNow('profiles.failedExport'))` — an error toast titled **“Failed to export profile”** (`i18n: profiles.failedExport`, `en.ts:1854`) — and the flow returns `null` (`:182-186`). The archive root gains one extra file, `desktop.json` (`DESKTOP_OVERLAY_FILENAME`, `:37`).
- **Config / env:** Reads the desktop appearance prefs (`skinPref`, `modePref`, `$userThemes`, `$profileColors`) and the layout store (`$layoutTree`). No env vars.
- **Edge cases / guards:** Missing `selectSavePath` bridge (non-Electron host) → `null`, silently, no toast. User cancel → `null`, no toast. Credentials are never included (backend guarantee). A built-in skin is exported by name only; only a user theme is inlined into `themes`. Strings go through `translateNow` rather than a React hook so the flow is callable from non-React surfaces (command palette, store).
- **Rebuild notes:** Minimal spec — resolve the profile, pick a save path with a `.tar.gz` filter, ask the backend to archive the profile with one extra JSON member describing UI state, toast the resulting path. Better version: let the user choose what rides along (skills? cron? layout?) with a checklist, show the archive size before writing, and sign the bundle so an importer can verify provenance.

### Profile import bundle (“Import profile…”)  `id: gapfill-desktop-b-r0.profile-import-flow`
- **Surface:** Desktop app
- **Where:** Three doors, all funnelling into `runImportProfileFlow()`: the sidebar filter menu → **“Profile”** submenu → **“Import profile…”**, the profile rail button **“Import profile…”** (and the condensed `ProfileDropdown`'s `onImport`, `profile-switcher.tsx:456`), and the command palette row **“Import profile…”** (`profile.import`). Native open dialog titled **“Import profile…”** (`i18n: profiles.importProfile`, `en.ts:1849`). Implementation `apps/desktop/src/store/profile-share.ts:191-218`.
- **What it does:** Reads a `.tar.gz` profile bundle, creates a new profile from it, applies the sender's desktop look (theme, mode, rail colour, layout), and drops the user into that profile on a fresh chat.
- **How it works:** `runImportProfileFlow()` calls `window.hermesDesktop.selectPaths({title, multiple: false, filters: ARCHIVE_FILTERS})` and takes `paths[0]`; a cancel returns `null`. It then calls `importProfileBundle(archive)` (`:138`) → `importProfileArchive(archive, name?)` (backend) → `applyDesktopOverlay(result.name, result.desktop)`. `applyDesktopOverlay()` (`:91`) is four independent best-effort steps, so a malformed half never blocks the rest and a missing overlay (a plain CLI-exported archive) is a no-op: (1) install every bundled theme with `installUserTheme()` inside a `try/catch` — an invalid or built-in-colliding theme just does not install; (2) assign `skinPref` only when `resolveTheme(overlay.skin)` actually resolves, so the pref never points at nothing, and assign `modePref` only for `'light' | 'dark' | 'system'`; (3) `setProfileColor(key, overlay.profileColor)` when it is a non-empty string; (4) adopt `overlay.layoutTree` when `isLayoutNode()` accepts it and `normalize()` returns a tree — then `$layoutTree.set(tree)`, `persistTree()`, `markActivePreset('custom')`. On success the flow mirrors `CreateProfileDialog`'s landing: `await refreshActiveProfile()` then `selectProfile(name)` (`:209-210`).
- **Inputs / options:** No arguments. Open dialog: single selection (`multiple: false`), filter `[{extensions: ['tar.gz', 'tgz'], name: 'Hermes profile'}]`. `importProfileBundle(archive, name?)` accepts an optional override name, but the flow does not pass one — the archive's own profile name is used.
- **Outputs / side effects:** Creates a new profile on the backend, installs any user themes the bundle carried, rewrites the desktop appearance prefs for the new profile key, may replace the **global** window layout tree, refreshes the profile list, and switches into the new profile on a fresh chat. On success, a success toast titled **“Profile imported”** (`i18n: profiles.imported`, `en.ts:1851`) whose message body is the new profile name (`:206`). On failure, `notifyError(error, translateNow('profiles.failedImport'))` — an error toast titled **“Failed to import profile”** (`i18n: profiles.failedImport`, `en.ts:1853`) — and the flow returns `null` (`:213-217`). Returns the new profile name or `null`.
- **Config / env:** Writes `skinPref` / `modePref` per profile key, `$profileColors`, `$userThemes` and the persisted layout tree. No env vars.
- **Edge cases / guards:** Missing `selectPaths` bridge or no file chosen → `null`, silently. An archive with no `desktop.json` imports fine and changes nothing about the look (`applyDesktopOverlay` returns early when the overlay is not an object). The layout tree is deliberately global — importing a profile can therefore change the window layout the user sees in every profile, and a junk tree is rejected by `normalize()` leaving the current layout alone. Name collisions are the backend's to resolve (the flow just reports whatever name comes back). Credentials never travel in the bundle, so an imported profile may need its keys re-entered.
- **Rebuild notes:** Minimal spec — pick an archive, ask the backend to unpack it as a new profile, then apply a versioned JSON overlay with per-step try/catch, refresh, and switch. Better version: show a preview of what the bundle will change (theme, layout, skills, cron) with per-item opt-in before applying, and never let an import silently replace a *global* layout — scope the layout to the imported profile.
