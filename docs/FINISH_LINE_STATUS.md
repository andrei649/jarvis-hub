### Key repairs included in the 2026-11-27 integration

- **Native Windows standard Chrome (`agents/core/browser_profile.py`, `agents/core/browser_windows_journal.py`).** Setting explicit owner `O:{sid}` in the disposable profile SDDL prevents Windows from assigning `Administrators` (`BA`) as default owner under UAC split-token, allowing Medium-integrity stock Chrome `158` to open `--user-data-dir` while keeping the directory strictly private (`SY`, `BA`, `{sid}` protected inheritable DACL). Bounded sharing-violation retries in `remove_owned_profile` cleanly wait out `chrome_crashpad_handler.exe` exit.
- **Provider probe OAuth isolation (`agents/core/llm/provider_probe.py`).** Empty `auth_env=""` on OAuth profiles (`chatgpt-plan`, `nous`) no longer cross-matches in `_key_for_elsewhere()`, fixing `tests/test_h380_provider_probe.py`.
- **Windows private-file ACLs and native test parity (`apps/jarvis-os/vault_index.py`, `agents/core/mcp/host_requests.py`, `agents/core/mcp/resources.py`, `agents/core/tool_result_store.py`, `agents/cli/nerva.py`).** Private files created on Windows use explicit current-SID SDDL ACLs verified by `assert_private_file`, reparse points are refused before `os.open` where `O_NOFOLLOW` is absent, and stdio/symlink fixtures handle non-Developer-Mode Windows cleanly while preserving full coverage on Linux and Windows CI.
- **Linux headless Chrome orphan supervisor (`tests/browser_orphan_fixture.py`).** Disabling session D-Bus/GPU/dev-shm stalls and widening the cold-start readiness budget eliminates the Ubuntu CI `native readiness expired` flake before the orphan reaper runs.
- **Backlog and documentation hygiene (`BACKLOG.md`, `docs/OWNER_TASKS.md`).** Retired tasks for removed Worldview/Argus and Slack/Discord surfaces (`DRA-08`, `L8140`, `L8188`, `HA-4i` scope) so remaining open entries reflect genuine owner gates or explicitly frozen post-finish-line areas.
