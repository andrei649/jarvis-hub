## Ce înseamnă terminat

Un rând este echivalent când cerința acceptată are implementare completă în Nerva,
inclusiv intrarea utilizabilă și limitele de autoritate necesare. O clasă, un adaptor,
un manifest, o rută fără client sau o demonstrație cu date fictive nu închid singure
rândul. Adaptarea la arhitectura Nerva este permisă; eliminarea unei cerințe doar
pentru a crește procentul nu este. Dacă rândul cere și generare și editare de imagini,
generarea singură îl lasă parțial.

Toate cele 697 de identități rămân fixe. Cele 107 decizii `skip` sunt excluderi de
produs păstrate explicit, nu funcții terminate. Ținta acceptată este de 590 de
rânduri; statusul arată atât procentul din 697, cât și cel din 590. O modificare
a excluderilor cere o decizie de produs documentată și o migrare explicită a
inventarului de referință. Niciun rând parțial nu primește automat 50% credit.

Statusul de pornire combină două clase de dovezi, afișate separat: auditul existent
din 7 septembrie și reevaluarea actuală a livrărilor recente. Nu pretinde că toate
cele 697 au fost reauditate acum. `keep` nu închide un rând cu stare inițială
`partial`; `update` nu devine terminat doar fiindcă descrierea veche spunea
`superior` sau `parity`. Exemplu: infrastructura de memorie poate fi superioară,
iar exploratorul cerut în același rând să fie încă incomplet.

**Verdict de cod și probă pe serviciul real sunt lucruri distincte.** ComfyUI,
Slack, GPU, memorie personală, aplicația nativă și furnizorii cloud au propriile
probe. Procentul de aici nu este un procent de pregătire pentru lansare. Un
backend configurat, un test simulat sau un build reușit nu afirmă proba live.

## Cum se menține statusul

[assessment.json](hermes/assessment.json) păstrează numai reevaluările explicite,
legate prin ID și hash de inventarul original. Restul rândurilor au baza de audit
vizibilă. Hash-urile dovezilor sunt SHA-256 peste text UTF-8 cu newline normalizat,
astfel încât checkout-urile Windows și Linux să aibă același verdict.

Pentru un rând reevaluat, citește cerința completă cu `show`, inspectează codul și
testele, apoi actualizează evaluarea. `equivalent` cere cod și teste referențiate
și zero lipsuri declarate; acestea sunt condiții necesare, nu un înlocuitor al
judecății tehnice. Nu reîmprospăta hash-urile fără reevaluare. Un fișier schimbat
sau dispărut produce `needs_review`, nu o promovare implicită.

```text
python scripts/hermes_status.py summary --json
python scripts/hermes_status.py list --state partial --cluster media
python scripts/hermes_status.py show H515
python scripts/hermes_status.py write
python scripts/hermes_status.py check
```

Pagina principală și lista completă sunt generate împreună. Testele de integritate
verifică numitorul, excluderile, identitatea rândurilor, dovezile modificate și
sincronizarea documentelor. Fiecare implementare viitoare actualizează statusul
în același PR dacă schimbă un rând evaluat. BACKLOG rămâne sursa de prioritate.

### 2026-09-18 — H002 one scripted turn from a pipe

### 2026-09-18 — H481 the catastrophic-command floor holds for the spellings that defeated it

`hardline_match` no longer screens one spelling. The old single-pass body becomes `_scan_one`, and the public function screens the command in every spelling `_detection_variants` yields: as given, unwrapped from a shell wrapper (recursively to `_MAX_SHELL_DEPTH = 2`), and de-obfuscated with intra-word quotes and escapes collapsed so `mk""fs` reads as `mkfs` — type-preserving, so an argv stays an argv and a literal `;` inside one argument can never become a segment break. A non-string command is materialised **once** up front, which fixes a real one-shot-iterator drain: the variant pass used to consume the iterator and hand the scan an empty command, turning `hardline_match(iter(["rm", "-rf", "/"]))` from a refusal into a miss. The pass is additive by construction, and that is measured rather than argued: an 80,000-case differential fuzz against the pre-slice module cleared **zero** refusals.

**The review found two blocking majors and four false claims. Every one was reproduced against a real shell before it was believed, and all six are addressed here.**

**One decoy character defeated the whole mechanism.** The payload was taken as the token immediately after the first `-c`-shaped flag, and the search then stopped. A shell keeps parsing options until the first *non-option operand* — `/bin/sh -c -x 'echo RAN'` prints `RAN` — so `sh -c -x 'mkfs.ext4 /dev/sda'`, `sh -c -- 'rm -rf /'`, `sh -c -e …`, `sh -c -u …` and `sudo sh -c -- 'wipefs -a /dev/sda'` all returned `None`, and the transport-level reproduction reached the spawn seam. The slice's own transport test covered `-c <payload>` and `-cx <payload>` only, so it stayed green through all of it. The scan steps over options to the first operand now, `--` included.

**Pressing Enter was the other bypass.** A `sh -c` payload is a shell *script*, and a newline separates statements exactly as `;` does. The newline was squeezed into a space before segmentation, so nothing ever occupied a command position on line 2 and `sh -c 'echo hi\nmkfs.ext4 /dev/sda'` passed the floor — the most ordinary shape a payload takes. Unquoted newlines are separators now, in the segment list *and* in the flat text the patterns match, because `_CMD`'s command-position anchor needs one. The split is quote-aware: a newline inside a string literal is data, and splitting there would put ordinary prose into a command position and refuse it.

Two smaller holes closed with them. `_CMD` learned four more shapes a shell steps over on its way to the word it will execute — a brace group (`{ mkfs.ext4 /dev/sda; }`), a compound-command keyword (`if true; then mkfs.ext4 …`, `for i in 1; do wipefs …`), an assignment prefix (`FOO=1 mkfs.ext4 …`) and the same after a wrapper (`env FOO=1 mkfs.ext4 …`). And `busybox` was named as a shell but not as a command-position wrapper, so `busybox mkfs.ext4 /dev/sda` — the standard shape on exactly the container targets this module says it keeps the floor on — walked straight through.

**Four documentation claims were corrected rather than left standing.** The module said the gaps it leaves are "listed in full"; the review found five entries missing from that list, so the list now says what it is — the gaps this module knows about, not a proof there are no others — and names the obfuscated-argv-head one it had omitted. A comment said an over-matched flag shape "can add a refusal but never clear one"; it could, and the counter-example is recorded (`powershell /c -Command Stop-Computer` returned `None` where `powershell -Command Stop-Computer` refused), fixed by the same change as the first major. A count of "six Windows-only HARDLINE entries" is four entries and two Windows-only branches. And `test_hardline_variant_expansion_stays_bounded` promised a bound on work while measuring none — it is renamed to what it actually pins, which is the opposite: that depth-3 nesting is a deliberate miss, red when someone widens the cap.

**H481 is recorded partial, and the middle tier is the missing one.** The row asks for three stacked layers; this is the first, with its matching repaired. There is no severity/reversibility-tagged risky-pattern catalogue feeding the approval card's description, so `rm -rf ~/projects` is neither hardline nor pattern-classified and the owner's card still says "run this argv" rather than "recursive delete" — which the row's own rationale calls the point. No `approvals.deny` fnmatch list at hardline level, and no parser limits that themselves hardline-block an oversized payload.

Two pre-existing false positives are unchanged and named so nobody attributes them to this diff: `git commit -m "fix;mkfs.ext4 handling"` refuses, and `grep -r "(shutdown" docs/` refuses. And the variant pass costs a **measured** ~38 ms of synchronous work on a maximal 64x4000-character argv (219 ms against 181 ms on base), on the event loop, before every exec. No test measures that, and the one whose name implied it did not.

### 2026-09-18 — H497 neither pairing credential is written down, and the code is stretched

`SenderPairing._code` becomes `_code_hash`, a salted digest; each deeplink entry moves from being keyed by its raw token to being keyed by an opaque 8-byte id with the token's digest inside the entry. Verification hashes the candidate and `hmac.compare_digest`s two fixed-length hex digests, so neither the length nor any prefix of the stored credential leaks through the comparison and the deeplink failure reasons stay indistinguishable. A pre-H497 plaintext file is accepted once — an upgrade must not silently retire a code the owner has already handed out — and rewritten hashed, preserving each link's channel, `created_at` and `expires_at`. `_digest` encodes with `surrogatepass` so a lone surrogate, which `json.loads` produces happily and which the one pairing route a stranger can reach will accept, misses instead of raising. `atomic_write_json` lands every JsonStore file owner-only.

**The review found three false claims. Two of them were fixed by changing the code rather than the prose.**

The module docstring said the store "holds nothing that can pair anybody: a backup, a synced folder, a support bundle or an agent with read access to `memory_logs/` finds no usable credential." That is true of a deeplink token — 192 bits from `token_urlsafe(24)`, not recoverable, full stop. It is **false of the pairing code**, which is whatever the owner typed: a four-digit code was recovered from the store file by exhausting 10,000 candidates in **0.006 seconds**, and then used to pair.

The code is therefore stretched — PBKDF2-HMAC-SHA256, 240,000 rounds — with `kdf` and `rounds` stored beside each digest rather than read from the module at verify time, so raising the count later cannot lock an owner out of a code hashed under the old one. A record written by the first cut still verifies, and is upgraded in place on the next **successful** pair, which is the one moment the plaintext is in hand; a **failed** guess leaves the stored record exactly as it was, because nothing about the stored form may depend on what a stranger guessed. The deeplink token stays on plain SHA-256, deliberately and for the author's original reason: `redeem_deeplink` hashes the candidate once per *outstanding link*, so a slow hash there hands any stranger who can send `/start junk` a CPU lever, and at 192 bits of entropy there is nothing for stretching to buy. The two credentials face different threats and now get different treatment.

The second claim was the defence of that bare hash: the salt comment pointed at the store-wide guess budget. That budget is an **online** control held in memory. It has no bearing whatever on an attacker who has read the file — which is precisely the threat at-rest hashing exists to answer.

The third: `atomic_write_json` claimed the chmod-before-`replace` ordering left no readable window, since `replace` moves the tmp's inode over the target. The ordering is the better of the two and it does not close the window it claims to: `write_text` creates the tmp at `0o666 & ~umask` — 0644 on a default umask — and the entire payload is in it before the chmod runs. The write now goes through a descriptor opened 0600, so the file never exists in any other mode with content in it. The test that pins it neutralises `os.chmod` entirely and still requires 0600, which is what separates the two implementations.

**H497 is recorded partial, and this is gap (a) of four.** Still owed, from the row: no lockout after N failed attempts (the row wants 1 h after 5, checked *before* the pending lookup); no verified revocation reaching live adapters; no admin-vs-user command split with a `{help, whoami}` floor. Unaddressed from the Hermes column: the code's 1 h TTL, "max 3 pending per platform", "1 request per user per 10 min", `unauthorized_dm_behavior` treating inbox-shaped platforms differently from chat-shaped ones, and the ordered authorization union that `is_allowed`/`gate_inbound` still approximate ad hoc.

**And the honest limit on what this does close.** Stretching is a work factor, not a wall. A four-digit code goes from milliseconds to minutes; an eight-character mixed-alphabet code becomes infeasible. Nothing enforces a floor on what the owner types — `PairingCodeBody` caps the length and sets no minimum — and generating the code for them, which is the row's own prescription, is not implemented. Until it is, the at-rest guarantee for the code is exactly as strong as the owner's choice, and the module says so in those words rather than the ones it used to.

### 2026-09-18 — H042 a taken port names itself instead of a raw errno

`serve.py` gains `probe_bind(host, port)`, called from `main()` after the posture guards and before uvicorn binds. A busy port prints the exact address, the command that identifies the holder (`nerva status`) and the way out (`JARVIS_PORT`), then exits **12**; `EACCES` on a privileged port exits **13**. The point is the *distinction*: uvicorn's `STARTUP_FAILURE` is **3** for every startup failure alike, so until now "the port is taken" and "the lifespan crashed" were the same exit code to a supervisor and the same wall of traceback to the owner. That collision was the defect, not the wording.

**The probe is a diagnostic, not a lock, and the safety case is the whole design.** It binds and closes immediately, reserving nothing — so the probe-to-bind race is real and deliberate, and losing it falls back to exactly today's raw error. Any `OSError` outside the two named arms is swallowed, because an unexpected probe failure must never turn a boot that would have worked into a refusal. The socket **constructor sits inside the guarded region** as well, and that arm is load-bearing rather than theoretical: `JARVIS_HOST=::1` on a box with no IPv6 stack raises `EAFNOSUPPORT` from `socket.socket()` itself, and a first cut that built the socket above the `try` replaced uvicorn's one-line `could not bind on any address` + exit 3 with an 8-frame traceback + exit 1 — the diagnostic for H042 inflicting the exact ergonomics failure H042 exists to remove.

It also refuses to be stricter than the real bind. On POSIX it sets `SO_REUSEADDR`, because `uvicorn.Server.startup` binds via `loop.create_server` and asyncio sets it there (`reuse_address = os.name == "posix"`); a probe without it would refuse a port merely holding a TIME_WAIT connection from the instance the owner just Ctrl-C'd — a restart uvicorn would have completed. That half is *executed*: a test reproduces the TIME_WAIT state, asserts a plain bind really is refused there, and then watches the probe stay silent. The Windows half is read off asyncio's source and has never been run here; the test skips off POSIX and the docstring says so rather than implying coverage.

9 probe tests, and **both exit codes are asserted by execution rather than by reading the branch**. The `EACCES` arm cannot be staged as root, where a sub-1024 bind simply succeeds, so it runs in a child dropped to uid 65534 with `setpriv` — with every premise (POSIX, root, `setpriv` present, `ip_unprivileged_port_start > 1`, a child that actually reached `probe_bind`) checked and skipped on rather than faked. ### 2026-09-18 — H495 a credential cannot reach a log record
